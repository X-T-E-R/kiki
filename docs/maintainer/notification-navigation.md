# Notification navigation

Notification clicks use the existing scope navigator and timeline locator. `HostNotification.scope` captures the producing window's credential-free `homeId`, `scopeId`, `serverHomeId`, and `connectionRef`; `route` carries the session, optional agent, and optional `turn` or `interaction` query. Session-list observations without an exact agent or frame do not invent one. Merged notifications open `/activity` in the captured scope.

`NavScopeBoundary` is the only click consumer. It verifies explicit destinations even in the active scope, preserves the dirty-draft confirmation and source visit, and shows the existing scope recovery surface for missing or changed targets. Missing explicit notifications are not treated as deleted back-stack entries. Active connections are validated without rebinding the session or reopening a remote connection. Preparation waits for a cancelled predecessor's rollback before starting the next scope change.

The desktop uses `notify-rust` 4.18's typed `wait_for_response`: `Default` and the `open` action navigate, while dismissals, expiry and replies do not. Do not substitute `wait_for_action`: the Windows implementation maps a body click to `__closed`. Each click has a monotonic `navigationId`; native acknowledgement clears only that id. The Tauri adapter registers its live listener before draining pending clicks and discards duplicate or older deliveries. Cold page boot serializes the captured scope into Router state and verifies before mounting the target. The bridge still relies on a running process callback; this is not evidence of persistent OS activation after the entire desktop process exits.

The claim-matched fixtures are `src/host/{tauri,browser}.test.ts`, `src/lib/{awayNotify,navScope,navReading}.test.ts(x)` in `apps/kiki-gui`, plus the notification tests in `src-tauri/src/lib.rs`. These exercise bridge, Router and locator seams, not an actual OS click. Native acceptance must separately click the notification body and action button, with the target window already open and with its page booting, then check the exact space/session/agent/frame and the return visit. Use an isolated candidate desktop and test home; do not inject notifications into a user's running service.
