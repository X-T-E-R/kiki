# Source-owned adapters

Managed executor adapters change only when a caller posts `POST /api/executors/{id}/install` or `POST /api/executors/{id}/rollback`. The request and response a caller can rely on are in [Executor catalog and checks](../en/server/rest-api.md#executor-catalog-and-checks) and [执行器目录与检查](../zh/server/rest-api.md#执行器目录与检查). This page records which installer runs, where the bytes come from, and what a failed write or a failed installation record leaves on disk.

## Pinned npm releases

`MANAGED_ADAPTER_RELEASES` in `packages/agent-core-v2/src/app/agentExecutor/managedAdapterRegistry.ts` pins `claude-acp` (`@agentclientprotocol/claude-agent-acp` 0.84.0, entry `dist/index.js`) and `codex-acp` (`@agentclientprotocol/codex-acp` 2.0.0, entry `dist/index.js`). `ManagedAdapterService.install` packs the pinned tarball URL with `npm pack` into `<home>/.tmp/managed-executors/<id>/<installId>`. It rejects a filename that is not one `.tgz` segment, an empty archive, an archive larger than 32 MiB, and a sha512 mismatch. It then runs `npm install --prefix <home>/tools/managed-executors/<id>/<version>-<installId> --ignore-scripts --no-audit --no-fund --save-exact` on that archive. The installation record is written only after the entry file exists and `package.json` name and version match the pin. A failure before that write leaves the previous active record in place and sets `phase` to `failed`. Rollback of these releases swaps `active` and `previous` in the record. They have no `targetDir`, so rollback does not copy files. `GET /api/executors/installations` lists the pins at `phase: idle` with no `active` when nothing is installed, and does not install them.

## Bundle root

The source-owned set is `SOURCE_OWNED_ADAPTER_FILES`: `agy-cli-acp.mjs`, `agy-hook-registration.mjs`, `agy-permission-hook.mjs`, and `agy-mcp-plugin.mjs`. `scripts/external-harness/production-manifest.mjs` is the same list. Package, version `0.4.1`, and source `bundled:external-harness` live on that manifest as `SOURCE_OWNED_ADAPTER_PACKAGE`, `SOURCE_OWNED_ADAPTER_VERSION`, and `SOURCE_OWNED_ADAPTER_SOURCE`. Files under `scripts/external-harness` that are not in the list are not installed.

`getSourceOwnedAdapterRoot` in `apps/kimi-code/src/native/native-assets.ts` returns a directory only when all four files are present. It prefers the SEA asset `external-harness/agy-cli-acp.mjs`. When the caller did not pass an asset source or manifest, it then tries `./external-harness`, `../external-harness`, and `../../dist/external-harness` beside the module. `apps/kimi-code/src/main.ts` publishes a found root as `KIKI_SOURCE_OWNED_ADAPTER_ROOT`. When this process is not a SEA binary and that lookup finds nothing, the entry removes an inherited value of the same variable. A later install then uses the checkout walk below instead of a parent process's older extraction. A SEA or packaged process that found its own four files still publishes that directory. npm `lite` and `full` both stage the four files at `dist/external-harness`. The SEA manifest carries the same four under `runtime/external-harness/`. `apps/kimi-code/scripts/native/external-harness-assets.mjs` collects and copies them.

`ManagedAdapterService` uses `KIKI_SOURCE_OWNED_ADAPTER_ROOT` when that variable is set. A set path that does not contain every file fails with `Source-owned adapter resources are unavailable` and does not fall through. An unset variable walks up at most eight parents for `scripts/external-harness`, then tries `external-harness` beside the compiled module.

## Selection, install, and rollback

`sourceOwnedAdapterScript` selects an executor only when the selected source is one `node-script` whose basename is `agy-cli-acp.mjs`. A path lookup, ambiguous selection, or unknown id returns not found without changing files. A selected script whose path is relative after `~` and `${KIKI_HOME}` expand instead fails validation with envelope code `40001`. The id is the executor the caller selected.

Install replaces only the four names in the script's parent directory. Env, model, permissions, and `supports_mcp` are not rewritten: an existing false stays false, and an existing true stays true. Other files in that directory stay. Snapshots live under `<home>/tools/managed-executors/<id>/<version>-<installId>`. When the current four files differ from the bundle, the pre-write snapshot uses version `0.0.0` and source `snapshot:local-adapter`. The new bundle is snapshotted before production is replaced. A production copy that already matches the bundle, with the same stored version and integrity, returns without writing.

HTTP status comes from `projectManagedStatus` in `packages/kap-server/src/routes/agentProfiles.ts`. It has `id`, `release` (`package_name`, `version`, `integrity`, `source`, `entry`), `active`, `previous`, `phase`, and `error`. It omits `supportsMcp` and `targetDir`. Source-owned `active.version` is `0.4.1`, `release.source` is `bundled:external-harness`, and `release.entry` is `agy-cli-acp.mjs`.

Rollback of a source-owned install writes the previous snapshot over the four names, then swaps `active` and `previous`. A second rollback swaps those two copies again. Custom files stay where they are.

## Failed writes and failed records

A production read that fails for a reason other than a missing file stops before any write. The four files and the installation record stay as they were. A missing name is absent. If a later write fails, that name is deleted instead of being restored from bytes that were never read.

`replaceProduction` remembers each name it attempts. If a write throws, it writes the original bytes back for names that existed and deletes names that did not. The call then fails with the write error. If saving the installation record throws and the files were not already the bundle, install runs that same restore for all four names from the bytes read before the write, then fails with the record error. If the files already matched, a failed record update does not rewrite them. If saving the rollback record throws, rollback writes the active snapshot back over the four names, then fails with the record error. The stored record is the one from before that failed update. When install had not stored a record yet, it stays absent.

If the restore write itself throws, the call rejects with `Error2` code `CONFIG_INVALID`; HTTP maps it to envelope `40001`. Install also records `phase: failed` and the diagnosis in `error`. Rollback propagates the request error without updating those progress fields, so its later status must not be treated as proof that the rollback succeeded. The request diagnoses are:

- Restoring production bytes, including when the install-record update fails and putting the earlier bytes back also fails: `Source-owned adapter restore failed after a partial write: <cause>`.
- Putting the active snapshot back fails with `Source-owned adapter restore failed after the installation record update failed: <cause>`. That restore runs when the rollback record update fails, and also when the previous snapshot could not be applied and the active copy cannot be written back either. In the second case the record update has not run; the stored record is still the pre-rollback record.

A rollback that cannot read its previous snapshot, for a reason other than not-found, leaves the installed files and the active record in place and rejects with that read error. Pinned npm installs do not use this byte restore. Their record moves only after the pack and metadata checks above.

## Next spawn

`status().supportsMcp` is true only when the bundle can be read and the four production files match it. That value is not written into the executor document, so it stays independent of the preserved `supports_mcp` field. The next spawn reads the replaced files; an already-running process is not restarted. After a rollback to bytes that do not match the bundle, `status().supportsMcp` is false again. The HTTP status still omits the field.

The AGY adapter registers session-local stdio servers through `registerMcpPlugin`, under `.agents/plugins/<namespace>` in the session workspace. It keeps the native default main agent rather than selecting a custom agent. A new namespace is `k` followed by the full 128-bit session UUID encoded as unpadded base64url: 23 characters, without truncating the session identity. AGY validates the final tool name, `mcp_<namespace>_<server>_<tool>`, against `^[a-zA-Z0-9_-]{1,64}$`; long server or tool names can still exceed that limit. The adapter leaves those names unchanged rather than introducing colliding aliases.

Claude catalog IDs carry their reasoning level in the model name. The adapter validates an explicit effort against that suffix and passes the unchanged model ID without a separate `--effort` argument; other model families retain their existing launch arguments. The `launch.effort` audit field preserves the selected effort for exact native load. Older audits without that field continue to recover it from their recorded `--effort` argument.

Native load reuses the namespace in that session's `mcp_plugin_registered` audit record, including the older `kiki-acp-<UUID>` form. It requires fresh connections with the original server names. A recorded MCP binding without a namespace fails load instead of guessing a replacement. Owned-plugin recovery checks both namespace forms for that session; live owners, changed files and multiple ownership receipts are preserved for scoped recovery. Closing the session removes only its unchanged owned plugin.

Same-turn steering uses AGY's `PostInvocation` hook in `.agents/hooks.json`. The adapter registers its steering key only while a turn runs and removes it when the turn settles. A queued `_session/steering` message is returned from the hook as `injectSteps:[{userMessage}]` with `force_continue`, so it reaches the next model call of the same native turn. The result is `injected` after the hook takes the message, `promptRequired` when no turn runs or the turn ends first, and `deliveryUnknown` when writing the reply to the hook fails. `deliveryUnknown` is never replayed. A failed audit write after queueing or dequeueing does not drop or duplicate the message.

Kiki ends the adapter by closing its stdin first. The built-in `agy-cli` descriptor sets `stdinCloseGraceMs` to 5000 (`stdin_close_grace_ms` on an `[agent_executors."<name>"]` entry), so the adapter's `close()` removes its owned hook keys and plugins before platform termination. Other executors keep the default of 0. When the adapter is killed anyway, the next session in that workspace recovers owned resources whose owner process is dead; keys and plugins of live sessions and foreign edits stay unchanged.

The adapter records `prompt_sent` only after Node's `stdin.write` callback succeeds. This proves completion of the local stream write, not that AGY parsed or executed the prompt. Keep process launch, local delivery, and the native result separate when recovering a session; neither a launch record nor an absent delivery receipt authorizes replay.

The server generates the MCP bridge command with the existing `resolveKikiCliLaunch` resolver. A SEA host uses its running executable directly; a confirmed built `main.mjs` host uses its Node executable plus that entry. Neither route depends on a shell shim. Development and embedded hosts that cannot identify their CLI retain the existing `kiki` PATH command; callers supplying a source launcher must keep its Node loader arguments. An AGY bootstrap spawn failure closes its stdio bridge and reports the launch error instead of remaining connected to an open stdin stream.
