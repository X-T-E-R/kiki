# Source-owned adapters

Managed executor adapters change only when a caller posts `POST /api/executors/{id}/install` or `POST /api/executors/{id}/rollback`. The request and response a caller can rely on are in [Executor catalog and checks](../en/server/rest-api.md#executor-catalog-and-checks) and [执行器目录与检查](../zh/server/rest-api.md#执行器目录与检查). This page records which installer runs, where the bytes come from, and what a failed write or a failed installation record leaves on disk.

## Pinned npm releases

`MANAGED_ADAPTER_RELEASES` in `packages/agent-core-v2/src/app/agentExecutor/managedAdapterRegistry.ts` pins `claude-acp` (`@agentclientprotocol/claude-agent-acp` 0.84.0, entry `dist/index.js`) and `codex-acp` (`@agentclientprotocol/codex-acp` 2.0.0, entry `dist/index.js`). `ManagedAdapterService.install` packs the pinned tarball URL with `npm pack` into `<home>/.tmp/managed-executors/<id>/<installId>`. It rejects a filename that is not one `.tgz` segment, an empty archive, an archive larger than 32 MiB, and a sha512 mismatch. It then runs `npm install --prefix <home>/tools/managed-executors/<id>/<version>-<installId> --ignore-scripts --no-audit --no-fund --save-exact` on that archive. The installation record is written only after the entry file exists and `package.json` name and version match the pin. A failure before that write leaves the previous active record in place and sets `phase` to `failed`. Rollback of these releases swaps `active` and `previous` in the record. They have no `targetDir`, so rollback does not copy files. `GET /api/executors/installations` lists the pins at `phase: idle` with no `active` when nothing is installed, and does not install them.

## Bundle root

The source-owned set is `SOURCE_OWNED_ADAPTER_FILES`: `agy-cli-acp.mjs`, `agy-hook-registration.mjs`, `agy-permission-hook.mjs`, and `agy-mcp-plugin.mjs`. `scripts/external-harness/production-manifest.mjs` is the same list. Package, version `0.5.1`, and source `bundled:external-harness` live on that manifest as `SOURCE_OWNED_ADAPTER_PACKAGE`, `SOURCE_OWNED_ADAPTER_VERSION`, and `SOURCE_OWNED_ADAPTER_SOURCE`. Files under `scripts/external-harness` that are not in the list are not installed.

`getSourceOwnedAdapterRoot` in `apps/kimi-code/src/native/native-assets.ts` returns a directory only when all four files are present. It prefers the SEA asset `external-harness/agy-cli-acp.mjs`. When the caller did not pass an asset source or manifest, it then tries `./external-harness`, `../external-harness`, and `../../dist/external-harness` beside the module. `apps/kimi-code/src/main.ts` publishes a found root as `KIKI_SOURCE_OWNED_ADAPTER_ROOT`. When this process is not a SEA binary and that lookup finds nothing, the entry removes an inherited value of the same variable. A later install then uses the checkout walk below instead of a parent process's older extraction. A SEA or packaged process that found its own four files still publishes that directory. npm `lite` and `full` both stage the four files at `dist/external-harness`. The SEA manifest carries the same four under `runtime/external-harness/`. `apps/kimi-code/scripts/native/external-harness-assets.mjs` collects and copies them.

`ManagedAdapterService` uses `KIKI_SOURCE_OWNED_ADAPTER_ROOT` when that variable is set. A set path that does not contain every file fails with `Source-owned adapter resources are unavailable` and does not fall through. An unset variable walks up at most eight parents for `scripts/external-harness`, then tries `external-harness` beside the compiled module.

## Selection, install, and rollback

`sourceOwnedAdapterScript` selects an executor only when the selected source is one `node-script` whose basename is `agy-cli-acp.mjs`. A path lookup, ambiguous selection, or unknown id returns not found without changing files. A selected script whose path is relative after `~` and `${KIKI_HOME}` expand instead fails validation with envelope code `40001`. The id is the executor the caller selected.

Install replaces only the four names in the script's parent directory. Env, model, permissions, and `supports_mcp` are not rewritten: an existing false stays false, and an existing true stays true. Other files in that directory stay. Snapshots live under `<home>/tools/managed-executors/<id>/<version>-<installId>`. When the current four files differ from the bundle, the pre-write snapshot uses version `0.0.0` and source `snapshot:local-adapter`. The new bundle is snapshotted before production is replaced. A production copy that already matches the bundle, with the same stored version and integrity, returns without writing.

HTTP status comes from `projectManagedStatus` in `packages/kap-server/src/routes/agentProfiles.ts`. It has `id`, `release` (`package_name`, `version`, `integrity`, `source`, `entry`), `active`, `previous`, `phase`, and `error`. It omits `supportsMcp` and `targetDir`. Source-owned `active.version` is `0.5.1`, `release.source` is `bundled:external-harness`, and `release.entry` is `agy-cli-acp.mjs`.

Rollback of a source-owned install writes the previous snapshot over the four names, then swaps `active` and `previous`. A second rollback swaps those two copies again. Custom files stay where they are.

## Failed writes and failed records

A production read that fails for a reason other than a missing file stops before any write. The four files and the installation record stay as they were. A missing name is absent. If a later write fails, that name is deleted instead of being restored from bytes that were never read.

`replaceProduction` remembers each name it attempts. If a write throws, it writes the original bytes back for names that existed and deletes names that did not. The call then fails with the write error. If saving the installation record throws and the files were not already the bundle, install runs that same restore for all four names from the bytes read before the write, then fails with the record error. If the files already matched, a failed record update does not rewrite them. If saving the rollback record throws, rollback writes the active snapshot back over the four names, then fails with the record error. The stored record is the one from before that failed update. When install had not stored a record yet, it stays absent.

If the restore write itself throws, the call rejects with `Error2` code `CONFIG_INVALID`; HTTP maps it to envelope `40001`. Install also records `phase: failed` and the diagnosis in `error`. Rollback propagates the request error without updating those progress fields, so its later status must not be treated as proof that the rollback succeeded. The request diagnoses are:

- Restoring production bytes, including when the install-record update fails and putting the earlier bytes back also fails: `Source-owned adapter restore failed after a partial write: <cause>`.
- Putting the active snapshot back fails with `Source-owned adapter restore failed after the installation record update failed: <cause>`. That restore runs when the rollback record update fails, and also when the previous snapshot could not be applied and the active copy cannot be written back either. In the second case the record update has not run; the stored record is still the pre-rollback record.

A rollback that cannot read its previous snapshot, for a reason other than not-found, leaves the installed files and the active record in place and rejects with that read error. Pinned npm installs do not use this byte restore. Their record moves only after the pack and metadata checks above.

## Next spawn

`status().supportsMcp` is true only when the bundle can be read and the four production files match it. That value is not written into the executor document, so it stays independent of the preserved `supports_mcp` field. The next spawn reads the replaced files; an already-running process is not restarted. After a rollback to bytes that do not match the bundle, `status().supportsMcp` is false again. The HTTP status still omits the field.

The AGY adapter registers session-local stdio servers through `registerMcpPlugin`, under `.agents/plugins/<namespace>` in the session workspace. It keeps the native default main agent rather than selecting a custom agent. A new namespace is `k` followed by the full 128-bit session UUID encoded as unpadded base64url: 23 characters, without truncating the session identity. AGY validates the final tool name, `mcp_<namespace>_<server>_<tool>`, against `^[a-zA-Z0-9_-]{1,64}$`; long server or tool names can still exceed that limit. The adapter leaves those names unchanged rather than introducing colliding aliases.

Claude catalog IDs carry their reasoning level in the model name. The adapter validates an explicit effort against that suffix and passes the unchanged model ID without a separate `--effort` argument; other model families retain their existing launch arguments. The `launch.effort` audit field preserves the selected effort for exact native load. Older audits without that field continue to recover it from their recorded `--effort` argument.

Native load reuses the namespace in that session's `mcp_plugin_registered` audit record, including the older `kiki-acp-<UUID>` form. It requires fresh connections with the original server names. A recorded MCP binding without a namespace fails load instead of guessing a replacement. After acquiring the exact session's resume lease, load rereads the audit and rejects `cancel_requested`, `cancel_failed`, `cancel` with `resumeSupported: false`, or `tool_terminal_missing` with unresolved tools as `AGY_SESSION_RETIRED`. Cancellation records its request before stopping the process, so a reconnect cannot erase retirement while final receipts are still draining. Each new turn also records `native_turn_pending` before writing to native stdin. Only a processed native terminal result with no unresolved tools records `native_turn_reconciled`, after awaited tool and text notifications finish. An outstanding pending record rejects load as `AGY_SESSION_UNCONFIRMED` even when the native child has exited; retry after reconciliation, or inspect the native outcomes before choosing work in a fresh session. Load does not reconcile by replaying commands. Owned-plugin recovery checks both namespace forms for that session; live owners, changed files and multiple ownership receipts are preserved for scoped recovery. Closing the session removes only its unchanged owned plugin.

Same-turn steering uses AGY's `PostInvocation` hook in `.agents/hooks.json`. The adapter registers its steering key only while a turn runs and removes it when the turn settles. A queued `_session/steering` message is returned from the hook as `injectSteps:[{userMessage}]` with `force_continue`, so it reaches the next model call of the same native turn. The result is `injected` after the hook takes the message, `promptRequired` when no turn runs or the turn ends first, and `deliveryUnknown` when writing the reply to the hook fails. `deliveryUnknown` is never replayed. A failed audit write after queueing or dequeueing does not drop or duplicate the message.

Kiki ends the adapter by closing its stdin first. The built-in `agy-cli` descriptor sets `stdinCloseGraceMs` to 5000 (`stdin_close_grace_ms` on an `[agent_executors."<name>"]` entry), so the adapter's `close()` removes its owned hook keys and plugins before platform termination. Other executors keep the default of 0. When the adapter is killed anyway, the next session in that workspace recovers owned resources whose owner process is dead; keys and plugins of live sessions and foreign edits stay unchanged.

The adapter records `prompt_sent` only after Node's `stdin.write` callback succeeds. This proves completion of the local stream write, not that AGY parsed or executed the prompt. Keep process launch, local delivery, and the native result separate when recovering a session; neither a launch record nor an absent delivery receipt authorizes replay.

The server generates the MCP bridge command with the existing `resolveKikiCliLaunch` resolver. A SEA host uses its running executable directly; a confirmed built `main.mjs` host uses its Node executable plus that entry. Neither route depends on a shell shim. Development and embedded hosts that cannot identify their CLI retain the existing `kiki` PATH command; callers supplying a source launcher must keep its Node loader arguments. An AGY bootstrap spawn failure closes its stdio bridge and reports the launch error instead of remaining connected to an open stdin stream.

## Optional plugin accounts

The stable instance reference lives in [`executorInstanceConfigurationSchema`](../../packages/protocol/src/rest/executor.ts). A `plugin_account` selects a Plugin Host source and account; it does not change the original `agy-cli` or `codex-app-server` registration. The account-source SDK contract lives in `packages/plugin-sdk/src/harness-account.ts`. Executor account-list routes return display metadata only. Preflight lists the chosen source's accounts without preparing a connection or consulting the global engine login.

`harnessAccountProcess` prepares the exact source/account/instance at the process-spawn boundary and retains its lease until that process exits. Spawn failure releases it too. It sends the normalized proxy choice to the source, then launches the engine without an inherited outbound proxy so its local source connection stays direct. No connection key, endpoint or lease identifier enters descriptor revision data. AGY receives `--kiki-harness-account`; its bridge consumes the key and model list from the launch environment, removes those values from its own inherited environment, and injects the key only into its native child. The same permission settings retain `modelProvider: 'gemini'` plus the selected raw model's `gemini-api://models/<id>` custom entry and `TOOL_FORMATTER_TYPE_NONE`. `GOOGLE_GEMINI_BASE_URL` is the source root; AGY appends `/v1beta`. The account's model list replaces `agy models`. Native title requests use that same endpoint and capability.

Plugin-account preflight probes `--kiki-harness-account-version`, so an old bridge that only supports global execution cannot pass as an account-capable bridge. The ordinary `--version` response stays unchanged to preserve existing global session bindings. Updating the source-owned bundle uses the same install/rollback path above. A native account child exit closes the account bridge after pending frames and owned-resource cleanup settle, releasing its source lease rather than keeping a dead connection available for another prompt. Source failure does not select a global account or replay a request.

Codex uses a custom Responses provider whose `env_key` names its private launch variable. Only the provider name, base URL and non-secret settings appear in argv. A source base URL ending in `/v1` is passed unchanged; Codex appends `/responses`. Startup and resume require Codex to confirm that provider before a user turn starts. The child environment key and source endpoint are redacted before incoming Codex protocol frames reach observers or transcript consumers.

## Command input and native event boundaries

For a new native conversation, the adapter leases `kiki-agy-command-guidance` in `.agents/hooks.json` before launching AGY. Its `SessionStart` command returns one persistent `injectSteps:[{systemMessage:{systemMessage}}]` instruction: use an explicit path such as `rg -n "pattern" .` for file-content searches and an explicit `-` when stdin is intended. A piped, open stdin otherwise makes pathless `rg` wait for input. The hook returns nothing outside the adapter's launch environment. Ordinary continuation, permission-mode restarts and exact native load do not register this instruction again. The lease uses the existing owned-key recovery and original-byte restoration; foreign hooks, including disabled entries, remain unchanged. An existing `"kiki-agy-command-guidance": {"enabled": false}` entry disables just this guidance without blocking launch or creating an ownership lease.

This is advisory tool-use guidance through AGY's documented native `SessionStart` contract. AGY retains its native permissions and tool results. The adapter neither inspects nor rewrites commands and keeps protocol stdin open. The [headless contract](https://antigravity.google/docs/cli/headless) exposes no tool-stdin control or stream-export unlock. [Native `agy acp`](https://antigravity.google/docs/cli/acp) became available in CLI 1.5.0 and reuses the CLI's login, tools and settings; it is separate from both this adapter's headless transport and the `agy_acp_server` executable used by `antigravity-acp`. The [1.5.1 release](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.1) fixes native ACP cancellation and late updates, but does not establish that ACP avoids head-of-line blocking behind an unfinished command. Keep the default route until the isolated comparison below establishes that behavior and its session contracts.

With `AGY_BRIDGE_AUDIT_DIR` set, `native_frame_received` records each parsed stdout frame before the delivery queue: launch-local `sequence`, `receivedAt`, event type, step index/type/state and terminal status. It contains no command, output or assistant text. `native_frame_delivered` records the same sequence after the event handler and awaited ACP notifications finish. Reception has its own audit queue, so a blocked notification cannot hide later frame arrivals. The 1 MiB ceiling applies to each NDJSON frame, not a burst containing several frames.

If a later frame is received while earlier delivery is unfinished, investigate the ACP notification path. If no later frame is received while the native transcript advances, investigate AGY's export path. A later native tool or text frame is forwarded without waiting for an earlier tool's terminal state. The turn still needs AGY's terminal result; a missing tool terminal update remains an explicit unknown-execution failure rather than a fabricated completion.

Cancellation stops the owned CLI and drains received frames before publishing missing-tool receipts. It preserves native tool success and failure even when the updates were queued behind another notification; a queued native result does not replace the cancellation with turn success. If stopping fails, the adapter freezes and drains the frames already received, preserving their tool outcomes before marking the remaining tools unknown. It then rejects the prompt and records `cancel_failed` without waiting for the live child to exit or claiming that it has stopped. Native disconnects and invalid stdout frames retain the original error and add `details.unresolvedTools` when there are pending tools. Valid frames preceding a malformed frame drain first, so an `ACTIVE` update and an invalid frame in the same chunk retain the known tool identity. Visible pending cards become failed receipts whose text says execution is unknown and must not be replayed. Native `ERROR` with `error: "interrupted"`, as captured in Paseo's `sigint-mid-tool` fixture, maps to ACP `cancelled`; a session with unresolved tools does not accept another prompt.

For a stalled live task, preserve its audit and native evidence, then verify the exact command PID, creation time and complete parent chain before an authorized intervention. Releasing a confirmed stdin wait can let the original native events and terminal result drain. A report file or a finished native assistant step alone does not authorize completing the Kiki task or replaying commands. Validate the original task's terminal receipt separately from any new-adapter fixture check.

### Compare native transports offline

`scripts/external-harness/agy-native-export-probe.mjs` drives the actual CLI against a synthetic Gemini endpoint. It requires an isolated Linux container, a previously obtained official AGY 1.5.x Linux binary, a Linux `rg` binary, and a cached Node 24 image. It creates a fresh home, supplies only a synthetic API key, checks that the guest has no external network route or D-Bus sockets, and writes `/out/report.json`. The script is excluded from installed adapter files.

From the repository root, set absolute host paths and choose one case per empty output directory. The output directory must be writable by container UID 1000. In Windows Git Bash, use `ROOT=$(pwd -W)`, Windows-form mount paths and `export MSYS_NO_PATHCONV=1`.

```sh
IMAGE=YOUR_CACHED_NODE_IMAGE_ID
AGY=/absolute/path/to/antigravity
RG=/absolute/path/to/linux-rg
ROOT=$(pwd)
TRANSPORT=stream
CASE=hold
OUT="$ROOT/.tmp/agy-native-$TRANSPORT-$CASE"
mkdir -p "$OUT"
docker run --rm --pull never --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 1000:1000 \
  --tmpfs /tmp:rw,nosuid,nodev,mode=1777 \
  --mount "type=bind,source=$AGY,target=/agy,readonly" \
  --mount "type=bind,source=$RG,target=/rg,readonly" \
  --mount "type=bind,source=$ROOT/scripts/external-harness/agy-native-export-probe.mjs,target=/probe.mjs,readonly" \
  --mount "type=bind,source=$OUT,target=/out" \
  --entrypoint node "$IMAGE" /probe.mjs "$TRANSPORT" "$CASE"
```

Run `stream hold` and `acp hold` first. The early command waits for stdin with pathless `rg`; a 12-second fixture timeout releases it. The synthetic model then requests a separate real command with an explicit stdin pipeline and produces final text. `beforeRelease.earlyExit` must be absent while the endpoint has already received `needle pipe` from the later command. Compare `laterToolBeforeRelease`, `textBeforeRelease` and `terminalBeforeRelease` to locate withheld events. A zero exit means the fixture completed; only those timing fields establish whether that transport exposes later events during the wait.

Use `explicit` to replace the early search with an explicit file path, `interactive` to send input to an explicit `rg -` through native `manage_task`, and `cancel` to cancel while the synthetic endpoint is holding the next reply. Each case checks that both native commands execute once. Completed turns and native ACP cancellation also exercise a second prompt and reject first-turn leakage. The test has bounded native response waits and terminates only its own child group during cleanup. If startup, a tool declaration or a native response differs, retain the nonzero report and fix the probe from that evidence before drawing a transport conclusion.

The native comparison remains unrun for this candidate: the shared Docker engine was unresponsive, and no alternate isolated runtime was admitted. Before routing production through `agy acp`, obtain the timed comparison plus native model/effort selection, permissions and explicit deny, additional directories, exact recovery, session MCP, account/proxy binding and cancellation evidence. Keep existing headless sessions on their saved route.
