# 角色、Bot 与房间

**角色（persona）**是一个跨会话保留记忆的身份，并有一个随时可以回去的固定地址；它的 [profile](./agent-profiles.md) 负责工具、权限、模型和执行方式。角色回答「它是谁、记得什么」，profile 回答「它能调用什么、怎么运行」，换掉 profile 绑定不会丢掉身份。**Bot** 是角色背后的常驻对话，定时提示词、另一个角色或房间都通过它找到这个角色；**房间**让多个角色在各自独立的成员会话里讨论同一主题。

## 从角色开始

在「角色」页创建角色，或把角色卡放到 `$KIKI_HOME/personas/release-guide/persona.md`（`$KIKI_HOME` 默认为 `~/.kiki`）：

```yaml
---
name: 发布向导
title: 发布协调人
job: 检查发布准备情况
profile: agent
greeting: 这次准备发布什么？
memory:
  shared: [global, workspace]
---
你负责协调发布准备工作。主动询问缺失的证据，区分已确认事实与待解决问题。
```

目录名就是稳定 ID：使用小写字母、数字，以单个连字符分隔单词。Markdown 正文定义身份。可选的 `model_alias` 和 `thinking_effort` 指定已配置模型及思考档位，但不授予权限；`tools` 等字段会被拒绝，因为权限属于 profile。

在 GUI 新建会话时选择角色，或从终端启动：

```sh
kiki --persona release-guide
```

每个角色都有一段固定的**日常对话**，侧栏那一行、切换器、会话顶栏和角色页打开的都是它，所以「找这个角色」每次都是同一段对话。一个角色可以同时持有多段，在它的对话列表里切换即可。终端里用 `/persona switch release-guide` 会打开**新会话**，旧会话保持原样；`/persona list` 列出全部角色。

显式选择的模型优先于角色模型；否则先看角色模型，再看 profile 或默认模型。显式选择其他 profile 会替换角色预设的 profile，但不会丢掉角色身份。

每个会话都会冻结自己的角色快照，编辑角色卡不会影响进行中的会话——新建会话或重建上下文后才会生效。开场白在你明确回复之前只是本地展示，打开会话不会把它写进模型历史。

## 记忆与角色卡

角色记忆跟随角色，不随 profile 或模型切换而丢失。角色专属条目与其他角色隔离，默认也能读取公共 global 和 workspace 记忆，设置 `memory.shared: []` 可排除。记忆页提供角色范围；模型、审批收件箱和可撤销的改动历史见[记忆](../guides/memory.md)。删除角色会一并删除其记忆，清理失败时删除操作会报错并保留角色卡，方便重试。

角色页支持 Character Card V3 的 JSON、PNG、CHARX 导入导出，保存前先看导入预览：lorebook 条目会转成角色记忆并影响后续模型请求。未知扩展字段在导出时保留，但头像之外的二进制素材无法完整保留，这类卡片请留好原件。头像选择器接受不超过 20 MB 的 PNG、JPEG、WebP，裁剪后上传 256 像素的圆形或方形图，重载后保留。**移除头像**只恢复首字母，不删除角色或记忆。直接调 API 上传仍限制 2 MiB。**复制**创建新身份，不带会话状态和私有记忆；**归档**把角色从常规选择列表隐藏，但保留数据。

保存后的 `persona.md` 上限 1 MiB，示例和扩展各 256 KiB，按 UTF-8 字节计算。超限内容会在改动角色卡和记忆之前失败，缩短后重试即可。旧版无效或超限的角色卡仍可用 `PUT /api/personas/{id}` 替换，或用 `DELETE /api/personas/{id}` 删除，后者会先清理该角色的记忆。

## 常驻对话

角色无论你有没有跟它说过话，都有一个稳定的地址。它的**日常对话**就是这个地址：侧栏那一行、切换器、会话顶栏和角色页打开的都是同一个；角色页还会列出该角色的其它对话，你可以把日常入口换成其中另一段。第一次打开时会创建它。

定时提示词、来自另一个角色的消息、房间里的席位访问的都是这同一个对话，不需要另外配置角色。它有独立的工作目录，默认 `$KIKI_HOME/bots/<id>`，也可以由角色卡用 `home_workspace` 指定。相关限制在 `config.toml` 里配置：

```toml
[bot]
enabled = true
max_handoffs_per_hour = 30
room_budget = 12
```

会话的 `delivery` 为 `reply` 或 `message`。在消息模式中，只有成功的 `SendMessage` 调用才算已发送消息，普通模型文本留在过程视图。用户触发的轮次如果只输出普通文本、没有成功发送，Kiki 会让模型重新考虑**一次**，因此可能增加一次模型请求。内置 `agent` profile 在消息模式中会暴露 `SendMessage`，reply 模式的轮次则不暴露。自定义 profile 如果显式设置了 `tools` 白名单，必须自行加入 `SendMessage`；delivery 模式不会绕过 profile 权限。工具表会在每个轮次内冻结，因此切换 delivery 会在下一轮生效。

`SendMessage` 可以发给用户，也可以用 `to: "@名字"` 发给另一个角色。同名时使用角色 ID。交接可以唤醒已关闭的常驻对话，并计入每小时上限；相同投递键的重试不会再占一个名额。附件是从会话工作区、附加目录或角色自己的区域复制的不可变副本，不能任意读取文件系统路径。

## 在房间中讨论

创建房间时选择两到六个成员、归类工作区和主持人。角色成员获得独立的消息模式会话；API 也接受现有线程（`kind: "thread"`），沿用其原会话、工作区和权限，要求 `[thread_communication] enabled = true`，且不能是 subagent。GUI 里可以在侧栏按住 Ctrl/⌘ 多选线程后选「拉进新房间」，在线程菜单用「加入房间…」，在房间「添加成员」的「线程」页签里加入，或在线程链接上选「和这些线程开房间」。谁会被唤醒由三条规则决定：

1. 用户 @ 谁就唤醒谁；`@everyone` 或 `@所有人` 选择全部成员。
2. 用户没有 @ 任何人时交给主持人，主持人不论是角色还是线程。
3. 角色或线程的房间消息只唤醒它 @ 到的成员。没有 @ 的发言会记入房间，但不会唤醒任何人。

角色成员依次运行，已有线程则各有自己的队列。静音成员不会被 Agent 提及和主持兜底唤醒，但用户显式 @ 它时仍会唤醒。成员收到自上次成功完成汇总以来的消息，不含自己已记录的发言。成功批次已经覆盖的通知不会再单独开启轮次；失败或取消的轮次不会确认该批消息已处理。

预算限制每条用户消息之后的成员发言数，默认 12 条。用尽后讨论暂停，「继续」重置预算并恢复保留的任务。「暂停」取消排队唤醒但让当前轮次跑完；「停止所有」还会中断角色成员的活动轮次，但不会中断原线程任务，也不回滚已完成的动作。纯角色房间保留用户插话，混合房间保留排队任务。同一时刻只展示一张问题卡，后续排队。

线程成员默认 `queueWhenBusy: true`：房间输入等当前轮次结束，不会 steer。冷线程在自己的工作区恢复；没有选中某成员的消息会在该成员下次唤醒时汇总，不单独产生模型调用。线程必须用 `ThreadSend({room, content, mentions?})` 发言，普通 Assistant 文本不会进入房间。`mentions` 使用准确的成员 ID（线程用 `sessionId`，角色用 `personaId`），不用显示名。不带 mentions 的发送不会唤醒主持人；主持人兜底只适用于用户消息。

改名、换主持人、静音和更换归类工作区都不会重写成员的系统提示词或权限。移除线程会在其会话留下系统记录、保留房间日志，不归档原线程。创建时要求两到六个成员，离开后可以少于两个。

成员无法唤醒时，房间会显示失败原因和恢复办法。模型未登录时，到「设置 → 模型与提供商 → 连接服务」登录，或打开该成员的会话选择一个可用模型——已有成员会话保留绑定的模型，改角色卡不会改变它。修好后再发一条房间消息，失败成员不是主持人时请 @ 它。「继续」恢复的是暂停的房间，不会重试尚未暂停的失败唤醒。

## API 入口

SDK 提供 `global.personas`、`global.bots`、`global.rooms`；HTTP 客户端还提供 `rest.personas`、`rest.bots`、`rest.rooms`。列表直接返回数组。创建会话接受 `persona` 和 `delivery`；读取会话会返回 `agent_config.persona = { id, name, avatarUrl? }` 以及 `delivery`。

REST 资源位于 `/api/personas`、`/api/bots`、`/api/rooms`。房间成员、静音、主持人和预算通过 `PATCH /api/rooms/{id}` 更新；暂停、继续和停止分别使用对应的 POST 动作。`GET /api/rooms/{id}/log` 接受 `afterId` 和 `limit`。角色记忆入口为 `/api/memory/persona?persona_id=<id>` 或 `/api/memory/persona_workspace?persona_id=<id>&workspace_id=<workspace>`。

认证与连接方式见 [REST API 指南](../server/rest-api.md)。
