# GUI 皮肤

皮肤决定 Kiki GUI 的外观：配色、字体、圆角和密度。Kiki 内置四套皮肤，你也可以用 JSON 文件添加自己的。

皮肤是纯声明式的。它只设置 design token，不能注入 CSS 规则或脚本，因此不会遮挡审批界面、不会在升级时把布局改坏，也不会执行代码。

亮色与暗色仍是单独的选择。一套皮肤可以只提供亮色变体、只提供暗色变体，或者两者都有；具体看到哪一个，仍由皮肤选择器上方的主题开关决定。

## 内置皮肤

| 皮肤 | 变体 | 是什么 |
| --- | --- | --- |
| **Paper**（默认） | 亮色、暗色 | 暖纸与墨，配赭红强调色。Kiki 自己的声音。 |
| **Slate** | 亮色、暗色 | 冷静的中性灰，配墨蓝强调色。界面外壳后退，代码是屏幕上唯一暖的东西。 |
| **High contrast** | 亮色、暗色 | 纯白或纯黑底，用可见的边框而不是暗示的边界，所有表面上的文字都达到 AAA。 |
| **Nocturne** | 仅暗色 | 深靛蓝纸面，配薄荷强调色。在亮色模式下它仍显示自己的暗色配色，设置页会说明这一点。 |

## 选择与微调

设置 → 通用 → 外观：

- **皮肤** —— 选择任意内置皮肤，或主题文件夹里的皮肤。立即生效。
- **微调** —— 在所选皮肤之上覆盖强调色、界面字体、代码字体、圆角和密度。改动会实时预览，点保存后保留。
- **导出为皮肤文件** —— 把当前所见完整写成一个 `.json` 皮肤文件，可以放进主题文件夹或分享给别人。

## 主题文件夹

皮肤文件与 TUI 主题放在同一个目录：

- `~/.kiki/themes/`
- 设置了 `KIKI_HOME` 时则是 `$KIKI_HOME/themes/`

目录不存在就自己创建。**文件名就是皮肤 id**：`ocean.json` 在选择器里显示为 `Ocean`。文件名只能用小写字母、数字和连字符。

放好文件后，在「外观」里点**重新加载皮肤**，不需要重启。

::: warning 是哪台机器上的目录？
Kiki 读取的是**运行 kap-server 那台机器**上的目录，因为那是服务端唯一能看到的文件系统。

- **桌面版** —— 就是你自己的 `~/.kiki/themes/`，符合直觉。
- **浏览器连接远程服务端** —— 这个目录属于那台服务端，不是你正在浏览的设备。内置皮肤在任何情况下都可用，因为它们随应用本身一起发布。
:::

Kiki 只会**读取**这个目录。导出皮肤只是把文件交给你，由你自己放进去。

## 编写皮肤

最小的皮肤只写要改的部分：

```json
{
  "kind": "kiki-skin",
  "version": 1,
  "name": "Ocean",
  "variants": {
    "dark": {
      "colors": {
        "paper": "#0b2126",
        "accent": "#ff8d7a",
        "onAccent": "#2b0a05"
      }
    }
  }
}
```

顶层字段：

- `kind`（必填）：固定为 `"kiki-skin"`。同一个目录里靠它区分 GUI 皮肤和 TUI 主题。
- `version`（必填）：固定为 `1`。
- `name`（必填）：选择器里显示的名称。
- `id`（可选）：默认取文件名。
- `description`、`author`（可选）：显示在选择器里。
- `variants`（必填）：至少包含 `light` 或 `dark` 之一。

每个变体可以有 `colors`、`fonts`、`shape`。没写的沿用默认值，所以部分覆盖完全可行。

### 颜色 token

所有值都是 `#rgb` 或 `#rrggbb`。

| Token | 控制什么 |
| --- | --- |
| `canvas` | 侧边栏所在的应用底面 —— 最低的一层 |
| `paper` | 抬起的对话纸面，主要阅读表面 |
| `panel` | 检查器、预览和浮动卡片 —— 最高的一层 |
| `hairline` | 安静的分隔线和输入框边框 |
| `hairlineStrong` | 强调边框、悬停边框 |
| `ink` | 正文文字 |
| `inkSoft` | 次级文字、标签 |
| `inkFaint` | 提示、计数、时间戳 |
| `accent` | 唯一的强调色：主按钮、链接、聚焦环、流式光标 |
| `accentDeep` | 强调色的悬停/按下态 |
| `accentSoft` | 强调色的淡色铺底 —— 选中行、搜索命中闪烁 |
| `accentInk` | 当作**文字**用的强调色 —— 链接、行内强调。不写则由 Kiki 从 `accent` 派生 |
| `onAccent` | 填充强调色**之上**的文字。必须设置，否则浅色强调色上会配出读不清的白字 |
| `amberInk`、`amberCard`、`amberRule` | 注意/警示角色：待审批、过期标记 |
| `success` | 成功状态、diff 新增行 |
| `danger` | 错误、破坏性操作 |
| `onDanger` | 填充危险色之上的文字 |
| `bubbleUser` | 你自己的消息气泡 |
| `scrollbar`、`scrollbarHover` | 滚动条滑块 |
| `shell` | 恒为深色的岛：终端、工具输出井 |
| `shellInk`、`shellInkStrong`、`shellInkSoft` | 深色岛内的文字 |
| `shellDanger` | 深色岛内的错误 |
| `shellHairline`、`shellHover` | 深色岛内的边框与悬停铺底 |
| `termScrollbar` | 终端内的滚动条 |
| `shadowInk` | 阴影和模态遮罩混合所用的颜色 |

::: tip 让文字保持可读
Kiki 内置皮肤保证每个文字 token 在 `canvas`、`paper`、`panel` 上都达到 WCAG AA（4.5:1），`onAccent` 对 `accent` 也一样。低于这个标准的皮肤仍会被加载 —— Kiki 不会否决你的选择 —— 但文字会变得难读。记得把 `ink`、`inkSoft`、`inkFaint` 对着三个表面都检查一遍。
:::

### 字体

```json
{ "fonts": { "sans": "'IBM Plex Sans', system-ui, 'PingFang SC', sans-serif" } }
```

- `sans` —— 界面文字
- `display` —— 标题和字标
- `mono` —— 代码、终端、数字

值**只能是字体族栈**。皮肤不能加载字体文件；只能写机器上已安装的字体，或 Kiki 已经内置的字体（`Instrument Sans`、`Newsreader`、`JetBrains Mono`、`Space Grotesk`、`Fraunces`）。括号、分号和花括号会被拒绝，所以 `url(...)` 根本无法表达。

字体栈结尾一定要放一个能显示中文的字体或通用族（`sans-serif`、`serif`、`monospace`），否则中文的回退不可预期。

### 形状

```json
{ "shape": { "radius": 14, "stageGap": 8, "spacing": 0.25 } }
```

- `radius` —— 纸面圆角，单位 px（0–28）
- `stageGap` —— 窗口边缘与浮动纸面之间的间隙，单位 px（0–24）
- `spacing` —— 密度单位，单位 rem（0.19–0.33，默认 `0.25`）。它会一次性缩放全应用的内边距和间隙，所以小改动影响很大。

## 出错时会发生什么

皮肤的设计前提是绝不把你锁在自己的界面外：

- **颜色或字体值非法**：只丢掉那一个 token，保留默认值，其余照常生效。「外观」里会列出被丢掉的内容。
- **无法识别的 token**：忽略，并在同一处报告。
- **出现意料之外的顶层字段**（例如 `css`）：整个文件被拒绝 —— 带着 token 之外的东西的文件不是皮肤。它会出现在被跳过的文件列表里，并说明原因。
- **JSON 格式错误，或是 TUI 主题文件**：跳过并说明原因，其他文件照常加载。
- **已选中的皮肤文件消失**：GUI 回退到默认配色并提示皮肤已丢失，而不是悄悄换成另一套。

## 分发

皮肤格式刻意设计成可以作为纯声明的插件内容直接分发：服务端会把已启用插件在 `x-kiki.themes` 中声明的主题与你自己的皮肤文件列在一起，并标注贡献它的插件。独立皮肤仍然可以直接分享 `.json` 文件，也可以随插件一起打包。
