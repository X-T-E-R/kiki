# 记忆

Kiki 记住那些你不想每个会话都重讲一遍的东西：你的代码希望怎么被审、上周确认过的哪个项目事实、参考资料放在哪。它默认开启，数据只存在运行 Kiki 的那台机器上，每次写入都会在对话里留下一行。

本页讲 **/memory** 页上的范围选择、可能挡在 Agent 和写入之间的审批收件箱，以及怎么关掉记忆。智能体在**单个会话内**能做的事（压缩、消息队列、任务看板）见[长时间的活](/zh/features/long-work)。

::: warning 注意 多个 Kiki 共用同一记忆目录
比 0.3.2 旧的 Kiki 不认识下面的**内容依据**和**有效性**字段，它的一次写入可能把这两个字段从条目上抹掉。如果两个 Kiki 共用一个记忆家目录——同一 `KIKI_HOME` 下的桌面版和 CLI，或者回滚到旧构建——请把每一侧都升到 0.3.2 或更新版本。已经丢掉的字段 Kiki 不会替你补回来：那条条目会显示**未记录**，要填回去只能依据当初的指令或资料，把依据和核对条件重新记一遍。
:::

## 智能体记住什么

记忆不是对话记录，也不是缓存，而是会话结束时会丢掉的那一小撮长期事实；任务进展属于 Agent 的工作笔记。一条条目只讲一个主体，放在一个位置：一句你以后还认得出的标题，加上**完整**的当前内容，包括决定它何时生效的条件。Agent 是整篇替换内容，而不是往上追加；更正过程和被淘汰的旧值留在改动理由里，不留在规则正文里。条目正文上限 1,500 字符，一个范围同时容纳 300 条生效条目；超过任一上限，Agent 会合并到已有条目，而不是另起一条。

Agent 用 `MemoryWrite` 写，用 `MemorySearch` 和 `MemoryRead` 读。搜索支持部分词命中，也支持不加空格的中文短语。原生 subagent 默认拿到两个只读工具，`MemoryWrite` 始终只给 main agent。

搜索分两种模式。默认按主体、标题或别名检索，返回排序后的 8 条一页；`mode: "list"` 不带 query，按页浏览清单，每页 20 条。两种模式都会说明实际查了哪些范围和状态、结果是否完整、有没有记录被跳过或读不出来。检索片段最多 200 字符，**会省略条件**——要依赖某条记忆、合并它或替换它之前，先完整读出来；搜不到只说明没有条目用到这些词。

main agent 的 `TodoList` 笔记可以在 `directives` 和 `decided` 里用条目 id 引用记忆，比如 `[m_id]`。压缩时，交接文本会带上每条被引用条目的当前标题、跟随替代条目，并把已归档的条目标为已撤回。

## 依据与有效性

一条条目可以记录关于自己的两件事，它们都会改变你该怎么看这条记忆。

**内容依据（basis）**说明内容从哪来：`human`（你要求或接受的）、`observed`（可核查的材料或观察）、`derived`（Kiki 自己的推断或转述），或 `unknown`。详情页会把每一种写成人话，并列出背后的说明和来源定位。早期条目没有记录依据时显示**未记录**——这是记录本身的缺口，不是对内容的判断。等你手上有了可以核对的材料，可以让 Kiki 为那条记忆补记依据和复核条件；这两个字段由记忆工具写入，**/memory** 页上的编辑器不提供输入框。Kiki 不会凭空编一个，也不会因为写入恰好发生在你的轮次里就把一条内容算成你亲口说的。

**有效性（validity）**说明依赖一个会变的事实之前要核什么。它带一个 `check` 写明该验证什么，可以再带一个 `until` 时间戳。带 check 的条目显示**依赖前：重新核对**；过了 `until` 的显示**已过期**，条目仍留在盘上作为历史线索，而不再是可以直接采信的前提；没有记录有效性的条目会显示「没有记录复核条件」。到了 `until` 也不会自动删除或归档任何东西。

在页面上修改条目的标题、类型或正文时，已记录的依据与复核条件会保留。依据或复核条件需要变化时，让 Kiki 同时更新它们。工具层的合同见[内置工具](/zh/reference/tools#记忆类)。

## 这一页让你选什么

在 **/memory** 页上，你选的是「正在看哪一部分记忆」，而这一页始终提供同样的三个选择：

- **全局（Global）**——所有项目共享。
- **工作区（Workspace）**——单个项目的存储。
- **角色（Persona）**——某个角色自己的存储，跟着这个角色跨 profile 和模型。

角色专属条目与其他角色隔离。默认情况下角色也能读共享的全局和工作区记忆；在角色卡上设 `memory.shared: []` 可以排除。工作区有自己的开关，可以跟随全局、单独开启或单独关闭——关掉之后已保存的条目仍然保留，只是 Agent 在那里不再读写。

角色还可以按单个工作区记笔记，所以一个跨项目的角色能自己保留项目相关的细节。

没有显式指定范围的新条目会落到当前绑定的角色上，没有角色时落到工作区；选范围既不会移动已有条目，也不会让你看到别的工作区或角色的记忆。

### 角色

角色的记忆跟着角色本身走，跨 profile 和模型都不会丢，所以换模型不会清空它知道的事。删除角色会一并删除它的记忆；清理失败时删除操作会报错并保留角色卡，方便你重试。见[角色、Bot 与房间](/zh/customization/personas#记忆与角色卡)。

条目是有类型的，类型就是你要筛选的维度：**关于你**、**反馈**、**项目**、**参考**。条目还可以是**置顶**（排在最前）、**生效中**、**被更新条目替代**，或**已归档**。

### 归档、替代与合并

让一条条目退出是状态变化，不是删除：正文仍在，**撤销**也照样能撤销它。规则真的变了时 Agent 会**替代**原条目——写出一条有自己 id 的新条目，把旧的标为**被替代**，两边的历史都留得住。当新条目完整覆盖了旧内容，Agent 也可以把旧条目标为**已并入**保留的那一条（详情里可以直接点进去看）；这个依赖会在真正执行归档那一刻重新核一遍，所以合并不会悄悄盖掉一条其替代者已经变了的规则。

## /memory 页

侧栏里 **/memory** 是常驻入口：记忆关着时它是「怎么打开」的说明，记忆开着时它就是管理台，可以搜索条目、按类型筛选、显示或隐藏已归档条目，点开一条就能读、改、置顶或删除。

工作区和角色都是可搜索的选择器，因为任一列表都可能有几百项。选了一个会清掉另一个，选择会带在 `?workspace=` 或 `?persona=` 参数上，所以指向某个范围的链接继续有效。

### 改动历史与撤销

对条目的每次改动都会留档。历史里的每一行都显示改动前后内容，并提供针对这一次操作的**撤销**，删除也一样——删除确认框说的正是「可以撤销」。

你打开着这条的时候它被改过，保存会被拒绝并提示先重新加载，你的修改不会盖掉新版本。重新加载后再改一次。

保存时标题、正文、置顶状态和已记录的属性都没有变化，就不会产生新版本，也没有可撤销的操作，页面会显示**无变化**。把刚保存过的编辑再提交一次，正常的落点就在这里。只改依据或核对条件同样算一次变化，会留下自己的版本。

## 审批收件箱

记忆审批有三种设置。默认的**自动**会把智能体提议的写入直接应用；改成**审查**，提议的更新或归档就会先等你处理。在**自动**下没有任何待处理内容，所以不会出现**收件箱**页签。

提议等待期间，原条目保持当前内容并继续生效。**保留**表示应用这条提议——更新会替换它所替代条目的正文，归档会归档那个条目。**丢弃**只去掉这条提议，原条目不动。提议不是生效的指引：Agent 不会拿它当前提使用，而且 Agent 自己无法批准它，只有你可以。

## 关掉记忆

**/memory** 页上有一个**使用记忆**开关，桌面版设置里也是同一个。关掉之后，Agent 不再读写记忆。

定期的长时记忆提醒是另一回事。只想停掉这些提醒、同时保留「新指令」和「压缩前」检查，在 `config.toml` 里设 `memory_maintenance = false`；记忆工具、审批和任务笔记照常可用。见[连续性提醒设置](/zh/configuration/config-files#连续性提醒设置)。
