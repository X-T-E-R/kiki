# 交互与输入

CLI 和 TUI 是一个终端界面，由输入框、对话视图和状态栏组成。本页讲输入与粘贴、审批流程，以及可以切换的模式。

## 输入框基本操作

输入框接受自由文本：`Enter` 发送，`Shift-Enter` / `Ctrl-J` 插入换行。输入框为空时按 `↑` / `↓` 浏览在当前工作目录输入过的内容，包括跑过的 Shell 命令。

**退出 CLI**：输入框为空时按 `Ctrl-D`，空闲时连按两次 `Ctrl-C`，或输入 `/exit`。三种方式都要求 Agent 空闲——流式输出期间 `Ctrl-C` 和 `Esc` 只是中断当前轮次。

## 粘贴图片与视频

图片和视频可以直接粘进输入框：报错截图、UI 设计稿、架构图、代码演示，粘进去就能讨论，不必先上传或转存。

操作方式：

- **macOS / Linux**：`Ctrl-V`
- **Windows**：`Alt-V`

粘贴后输入框里是一个可编辑的占位符，发送时会被真实内容替换。剪贴板里是纯文本就照常粘贴。能否使用媒体取决于当前模型是否接受图片 / 视频输入（`image_in` / `video_in` 能力字段）；登录 Kimi Code 账号后默认开启。

## 斜杠命令

以 `/` 开头的内容会被识别为斜杠命令。输入 `/` 后弹出补全菜单，随后续字符实时过滤；按 `Esc` 关闭菜单，匹配失败时内容会作为普通消息发送给 Agent。

已激活的 [Agent Skills](../customization/skills.md)（扩展 Agent 能力的技能包）会注册成斜杠命令：普通外部 Skill 用 `/skill:<name>` 调用，外部子 Skill 显示为 `/parent.child` 这样的点分命令，内置 Skill 直接是 `/<name>`。外部 Skill 名称不和系统命令冲突时，可以省掉 `skill:` 前缀直接输入 `/<name>`。

在长提示词里，空白字符后（包括后续行的行首）输入 `/` 会打开只含 Skill 的补全菜单，一条提示词里可以引用多个 Skill：Kiki 会一起激活并作为同一轮次执行，一次 `/undo` 撤销整次提交。提示词中的 Skill 引用只按名称激活，不能带参数；要传参数仍需单独写 `/skill:<name> args`。内置命令和 plugin 命令只能放在输入开头。

部分命令仅在 Agent 空闲时可用，流式输出或上下文压缩期间要先按 `Esc` 中断。`/yolo`、`/plan`、`/help`、`/btw` 等切换和查询类命令始终可用。全部命令见[斜杠命令参考](../reference/slash-commands.md)。

## 文件引用

键入 `@` 触发文件路径补全，选中后插入相对路径，Agent 读到这条消息时会直接加载该文件。git 和非 git 目录都可用；文件夹候选以 `/` 结尾，可以继续往下补全。Kiki 的文件快速搜索组件还在后台下载时，补全会先退回基础的文件系统扫描。隐藏路径会出现在候选中，`.git` 不会。

> `@` 和 `/` 是两套机制：`@` 给 Agent 补文件上下文，`/` 调用内置功能或 Skill。空白后的 `/` 只补 Skill，内置命令和 plugin 命令要用开头的 `/`。

## 审批流程

工具调用有副作用时（执行命令、在工作区信任边界之外改文件），TUI 会弹出审批面板。已信任工作目录内的 `Write` / `Edit` 不再逐项询问；manual 模式下，Shell 命令、工作区外写入、工作区里指向外部目标的链接和敏感文件访问都会先问。YOLO 模式下的普通工具调用、Plan 模式下对计划文件的写入都不触发审批。

用方向键选、`Enter` 确认，或按 `1`/`2`/`3` 直接选数字项。`Esc`、`Ctrl-C`、`Ctrl-D` 都表示拒绝。

面板通常提供「Approve for this session」，选中后本次会话内的同类调用自动放行。要跨会话生效的规则，在[配置文件](../configuration/config-files.md#permission)里写 allow / deny。

## 模式切换

### Plan 模式

Plan 模式下，Agent 先输出行动计划，等待你确认后才动手修改文件，适合复杂或高风险任务。

- 切换：`Shift-Tab` 或 `/plan`
- 清除当前计划：`/plan clear`（仅空闲时）

Agent 给出方案后会停下来等你：批准、拒绝，或要求修改。退出 Plan 模式需要你确认，即使开着 YOLO 模式也一样；Auto 和「替我审批」是例外，计划退出自动批准，并在记录里标为 "Auto-approved"。

### 权限模式

`/permission` 在 Manual、Auto、「替我审批」和 YOLO 之间切换。

**YOLO 模式**（`/yolo`）自动批准 Agent 的文件访问，包括 `.env`、SSH 私钥等敏感目标。显式 deny 规则仍优先，Git 控制路径仍可能询问。退出 Plan 模式仍要审核，Agent 也仍可能向你提问。

**Auto 模式**（`/auto`）自动批准普通工具调用和计划退出，访问敏感文件和工作区里指向外部目标的链接时才会问。显式 deny 规则仍会拦截，危险 Bash 命令默认也仍会请求审批，除非关掉该检查。

**「替我审批」模式**（`review`）和 Auto 一样处理普通操作，但策略产生的审批请求先交给[已配置的审查者](../configuration/config-files.md#审查者审批)。显式 `ask` 规则始终交给你。审查者高置信的决定会记录来源；不确定或审查者不可用时回到你的审批面板，同一轮里连续三次被拒后，这一轮余下的请求直接交给你。Agent 提问不经过审查者，是否阻塞当前轮由[交互设置](../configuration/config-files.md#interaction)决定。

没有审批接收方时（例如无人值守的定时运行），需要你确认的请求会被取消而不是放行，提问也会被撤销，不会一直挂着。

::: warning 注意
YOLO 模式会跳过文件写入和命令执行的确认，请只在受信任的工作目录下使用。
:::

### Shell 模式

Shell 模式让你不离开对话就能跑终端命令，输出写进对话上下文，Agent 在后续轮次能看到结果。

- 进入：在空输入框中键入 `!`，或粘贴以 `!` 开头的命令。
- 退出：在空输入框中按 `Backspace` 或 `Esc`；提交命令后也会自动回到普通模式。
- 召回历史命令：在 Shell 模式的空输入框中按 `↑`，召回后仍在 Shell 模式，可再次作为命令执行。

Shell 模式下输入框左侧显示 `!` 提示符（桌面版 GUI 中边框还会变紫）。例如 `!git status` 不用另开终端就能查看仓库状态，输出直接进入对话上下文。

## 流式输出期间

Agent 思考或调用工具时，输入框仍然可用，支持以下额外操作：

- **`Ctrl-S`**：把输入框中的内容立即注入正在运行的轮次，无需等待结束
- **`Esc` / `Ctrl-C`**：中断当前轮次
- **`Ctrl-O`**：全局切换工具输出和压缩摘要的折叠状态

## 外部编辑器

按 `Ctrl-G` 把当前输入发给外部编辑器，保存关闭后写回输入框，不保存则原样保留。输入大段文字或带格式内容时这样最省事。

编辑器选取顺序：`/editor` 配置 → `$VISUAL` → `$EDITOR`。三个都没有时，先运行 `/editor` 选一个。
