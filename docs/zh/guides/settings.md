# 设置页导览

Kiki 桌面版在**设置**对话框里提供偏好设置，在侧栏的「用量」等独立页面展示活动。本页帮你定位各项控制、了解它会改变什么；完整参考见各节链接。

**「我想改 X」速查表：**

| 我想改… | 去哪里 |
| --- | --- |
| 用订阅账号登录，或添加 API 密钥 | **模型与服务商 → 连接服务** |
| 版本与更新通道（Stable / Beta） | **关于与更新** |
| Agent 配置档案、提示词覆写 | **智能体** |
| 长期记忆的低频维护提醒 | `config.toml` 的 [`loop_control.continuity_cadence.memory_maintenance`](../configuration/config-files.md#连续性提醒设置) |
| 搜索与抓取的配置来源 | **搜索与抓取** |
| 输入框草稿是否记住 | **输入框（Composer）** |
| subagent 派发配置 | **派遣能力（Dispatch capabilities）** |
| 为 Agent 任务运行浏览器 | **浏览器控制** |
| 控制服务机自己的桌面 | **电脑控制** |
| 实验性功能 | **开发者 → 实验性** |
| 查看当前会话的提示词来源 | 会话标题栏 **⋯ → 提示词生效详情** |
| 暂时用预览区域显示驾驶舱 | 右侧面板标题栏**驾驶舱** |
| Token 用量与费用 | **用量 → 历史（Usage → History）** |
| 正在运行或排队的模型请求 | **用量 → 实时（Usage → Live）** |
| 模型／供应商请求并发 | **用量 → 实时 → 并发限制（Usage → Live → Concurrency limits）** |
| 把用量发送到其他服务 | **用量 → 外部同步（Usage → External sync）** |
| TUI 主题、编辑器等 CLI 侧偏好 | 终端里的 `/config` 等命令，见 [CLI 侧对应](#cli-侧对应) |

## 连接

**设置 → 模型与服务商 → 连接服务**（`/settings/ai?tab=providers`）是一份列表。Kiki 触达模型的每种方式都是一个**连接**——登录的账号、持有密钥的在线 API，或本机服务器——每个占一行，写明它如何被触达、带什么、是否可用。连接如何认证属于这个连接本身，不是需要另行同步的另一份清单。

**添加连接**是唯一的入口，只问一个问题——接哪个服务、用什么方式：

- **用账号登录**：本服务器提供的订阅——Kimi Code、用于 Codex 的 ChatGPT 账号、Grok Build 账号、GitHub Copilot。已有对应连接的账号不会再次出现；已失效的登录在它自己的那一行恢复。
- **从目录选**：从 models.dev 选一个服务，Kiki 填好地址和模型列表。若该 id 已存在，则更新那个连接，表单会在提交前说明。
- **自己填写**：协议、地址和密钥，适用于目录里没有的服务，包括本机服务器。

账号连接由登录写入，因此它的行里没有协议、地址或密钥可填。展开可看背后是哪个账号、服务方说还剩多少，以及改变登录的那一个操作：

- **已连接**：凭据可用，Kiki 会自行续期。**退出**只结束 Kiki 内的这次登录，并移除它带来的模型；不会退出该服务方的账号，也不影响服务方保存的账号信息。
- **登录已失效**：服务方已不再接受这次登录。**重新登录**在同一个连接上换掉它，列表里不会多出一行。
- **登录未完成**：流程结束但没有拿到凭据——你拒绝了、验证码过期，或中途失败。一行说明是哪一种，连接保持服务端如实报告的样子，不会留下半成品。
- **等待你确认**：登录正在进行，显示验证码、**打开验证页**、有效剩余时间，以及**取消登录**。

登录完成后，该账号的模型由服务端加入目录。要确认实际能用的模型，看 **可用模型**；这里的一行只报告连接与其登录状态。

在 Kiki 中退出只影响 Kiki。服务方保留你自己的订阅记录，重新登录会连回同一个账号。

### 复用本机已有的登录

对 ChatGPT（Codex）和 Grok Build，连接可以直接使用它们自己的 app 在本机已有的登录，而不必新建一个。Kiki 会复用它，并在它过期前主动续期；Kiki 不会复制凭据，也不会启动那个 app，在这里登录或退出都不会改变它那边的任何东西。

"本机"指 Kiki **服务端**所在的机器。通常就是你正在看的这台；当它不是时，**到服务端的其它目录中查找**可以指定要读取的目录。

**检测本机**会报告另一侧是哪个账号、凭据保存在哪里（文件、系统钥匙串或加密存储），随后出现的**使用这个登录**只接入刚报告的那个账号。期间被换掉的凭据会被拒绝，临近过期的凭据则直接使用并由 Kiki 续期。

当本机的凭据无法使用时，页面会给出你能据此行动的原因：没有该服务的账号、已退出、存放在读不到的位置，或属于另一个账号——并且不提供任何接入动作。

**停止使用**会放弃这个连接对本机登录的使用。它移除 Kiki 的引用和由此写入的模型；登录本身仍然保留在原处，另一个 app 不受影响。

### 超时

**设置 → 模型与供应商 → 连接**上有两个各自独立的超时，管的不是同一类请求：

- **请求超时**——本界面向 Kiki 服务端发起的普通请求的默认截止时间。
- **阅读超时**——读取会话历史或正文时，最多等待多久才放弃。默认值为 `0`，即不设总截止：会话再大、加载再慢也一直等。如果你更希望卡住的读取尽快失败，就设一个秒数。

阅读超时只约束「等多久」，不限制「能读多少」。改动后的值对**下一次**读取生效——不会中断已经在跑的读取，也不会触发重连。除非你确实想要一个上限，否则保持 `0`。这两项是界面设置，不是 `config.toml` 里的键；决定多少历史留在服务端内存里的是另一套预算，见 [`transcript_memory`](../configuration/config-files.md#transcript-memory)。

## 关于与更新

**设置 → 关于与更新** 显示当前版本，更新设置都在这里。**更新通道**选择 Stable 或 Beta，自动检查和手动检查都按这里的通道走。**自动检查更新**开关控制每天那次检查，关掉之后就只有点**检查更新**才会检查。**发现新版本时**决定那时怎么做：**通知我**弹出对话框，显示版本号和一小段变更摘要并等你决定；**下载并安装**则自己开始安装，不走那个对话框。两种模式都会在关闭还有运行中任务的空间之前先问你。

对话框的三个选择会被记住，不会每次重来：**明天再提醒我** 24 小时后再问，**跳过此版本**只让该通道的这个版本安静下来，两个方式下更新的版本都还会提示。安装前 Kiki 会重新核一遍通道和版本，底下已经变了的更新提议会被拒绝。某个选择没能保存时，对话框会留在原地请你重试。见 [Kiki 桌面版](../getting-started/desktop-app.md#更新)。

## 智能体

**设置 → 智能体** 选择一个工作区，查看其默认主 Agent 配置档案（profile）、生效来源和 subagent 能力。文件型 profile 可在其显示的来源处直接编辑。**设置 → 智能体 → 提示词字段** 编辑 `config.toml` 中的 `[prompt]` 提示词字段覆写段；卡片默认折叠——编辑前先展开。见 [Agent 与 subagent](../customization/agents.md#派遣能力可见性) 和[提示词字段与覆写](../customization/prompt-fields.md)。

长期记忆维护提醒按自己的周期运行。若只想停掉这些提醒、保留新的持续指示和压缩前检查，在 `config.toml` 中设置 `memory_maintenance = false`；记忆工具、审批和任务笔记照常可用。见[连续性提醒设置](../configuration/config-files.md#连续性提醒设置)。

## 通知与消息

**设置 → 通知与消息 → 系统通知**里的**允许系统通知**控制本设备的会话通知和跨空间待处理提醒。默认开启的**对话结束后通知**沿用 Kiki 在后台或隐藏时的通知途径。这里的结束是本次交办工作已收尾：主智能体已回复完毕，有限后台任务与 subagent 已收尾，结果和自动续跑也已处理完。仅一轮结束不会通知。常驻服务器、监听器和未来定时任务不会一直阻止通知；等待审批、提问、失败和用户停止不算完成。浏览器使用需要允许本站发送通知；若已拒绝，可在地址栏的网站权限中恢复。

手机或团队群的已配置通道，在各通道里开启**对话结束后通知**，采用同一工作收尾判定。**发送通知**仍是这些通道单独的总开关；之前关闭的总开关、连接和通道保持关闭。新配置默认开启，**跳过短任务**默认 `0` 秒，短答也能通知；提高此值只筛掉通道中的短任务通知，不改变完成的含义。系统通知开关保存在当前设备，通道规则保存在所连服务端；启动或重连不会补发旧的完成通知。

## 搜索与抓取

**设置 → 搜索与抓取 → 概览与配置来源** 查看内置搜索与抓取模块（`WebSearch` 和 `FetchURL` 两个工具背后的能力）当前生效的配置来源，并控制服务器是否复用本机的搜索配置。对应的配置位于 `config.toml` —— 见[配置文件](../configuration/config-files.md#nb-search)。

同一处的**高级与诊断**标签页里有一张**全文索引**卡片，用于搜索你自己的会话历史。首次索引在后台建立，优先处理最近的会话，卡片会显示已完成的数量。如果索引因可处理的原因停下，这张卡片会出现**重启索引程序**按钮；索引被配置关闭或不可用时则没有可重启的对象，卡片直接说明原因。

## 浏览器控制

**设置 → 浏览器控制**（`/settings/browser-control`）的第一屏是三个具名的接入方式。你挑一个，配置它，连接它——通常两步。

- **Kimi 浏览器扩展**：驱动你自己在用的浏览器，带着你自己的登录状态。Kiki 装插件和本地桥接程序；扩展要去浏览器商店加一次，那一步只能由你点，Kiki 不会替你越过。
- **独立浏览器**：由 Kiki 启动并维护自己的浏览器，登录状态独立，不碰你日常用的浏览器。**一键配置**下载并校验所需组件，之后 **连接** 启动它。
- **Codex / ChatGPT 浏览器扩展**：由 Codex / ChatGPT 桌面端控制，不由 Kiki 安装或连接；这一项只给出官方说明链接。

每一项都写着自己的状态和**还差哪一步**，并把下一步放在同一行：缺组件时是**一键配置**，只差商店授权时是商店链接，只差开关时是**开启浏览器控制**。Kiki 能装的都装好之后，这一项就不再催你安装，而是告诉你可以连了。检测器自己的话（哪些环节只是「报告」而非「验证」）收在**此服务检测了什么**折叠里，不占第一屏。

**开启浏览器控制**就是同一个同意动作，就在本页。只差这个开关时，那一次确认会补上还缺的组件（组件已齐则一个都不装）、启用插件，并为这台服务开启浏览器控制——三项在确认前都会写明。浏览器控制默认关闭，所以这一步就是把它打开的地方，不必去别的页面找开关。

如果本页之外有东西把浏览器控制关着——某个环境变量，或该主机上的运行时覆盖——这里任何操作都改不动。该项会直说这一点，而不是给一个按了也没用的按钮；**看是什么把它关着**会指出具体的覆盖来源。

**高级：编辑已有连接，或接上一个你自己已经开着的浏览器**折叠区里是手填的部分：每条连接有固定 id、显示名称、启用开关，以及两种指向不同目标的接法之一——

- **独立 Agent 浏览器（Profile）**：Kiki 在服务机上启动并管理它自己的浏览器，使用它自己的 profile（登录态），不会复制你日常浏览器的 cookie。可选：改用已安装的 Chrome 或 Edge，以及**显示浏览器窗口**（默认关闭，即无头运行）。
- **已有或远端浏览器（CDP）**：附着到已经开放 CDP 地址的浏览器，不新启动任何东西。该地址指向浏览器所在的那台机器，可能是另一台机器。

每条连接都可以单独**检查**、**连接**、**断开控制**。检查会启动受管驱动并读取会话与标签状态，CDP 连接则与端点握手并列出目标，两者都不会打开页面。保存只写配置，并会先结束该连接当前正在运行的会话。**断开**释放该连接：借用的 CDP 浏览器保留，Kiki 启动的实例会关闭。**新会话默认浏览器**只对新创建的会话生效；关闭一条连接不会自动换上另一条。

驱动，以及 Kiki 启动的任何浏览器，都运行在 Kiki 服务机上，而不是显示这个窗口的设备上；组件存放在运行它们那台机器的 `<Kiki home>/browser/resources` 下。

Agent 通过[浏览器工具](../reference/tools.md#浏览器类)使用这些连接，并且只按连接 id 指定，不按显示名称。开关与连接本身分别保存在 [`[experimental]`](../configuration/config-files.md#experimental) 和 [`[browser_control]`](../configuration/config-files.md#browser-control)。

## 电脑控制

**设置 → 电脑控制**通过一个固定版本的开源执行器，控制运行 Kiki 服务的那台机器的桌面。默认没有安装或配置任何东西，所以页面初始为空。

**安装执行器**会下载并校验该发行物，然后注册一条名为 `kiki-computer` 的全局 MCP 连接（驱动路径加上 `mcp` 参数）。**已安装**只表示文件校验通过——不代表真的能控制桌面，安装过程也不会去检查这一点。页面会说明将被控制的机器：**Kiki 服务机**就是当前连接的服务，因此在远端或 SSH 连接下，桌面属于那台主机自己的图形会话。

Agent 通过现有 MCP 机制与权限使用执行器自带的工具——见 [MCP](../server/mcp.md)。固定版 Windows 执行器只观察主屏，无法自行选择显示器。macOS 上桌面权限由调用进程承载，需要时在驱动报告缺失处授予。

**停止控制**会结束本服务启动的 cua 进程并停用可编辑连接的配置；其他客户端或另一个 Kiki 实例可能仍在操作该桌面。

## 输入框（Composer）

**输入框 → 保留输入草稿** 开关（英文界面为 Composer → Persist composer drafts）控制新会话选择（模型、思考强度、工作区、工作目录、profile）和每个会话的草稿文本是否写入当前浏览器。关闭开关会清空已保存的存储。见[工作区与会话管理](./sessions.md#会话存储)。

## 派遣能力

打开**派遣能力**（Dispatch capabilities）面板 —— 位于新会话工作区选择器旁，或某个会话的右侧栏 —— 查看 subagent 的 profile（配置档案）、route（路由）与 executor（执行器），以及默认模型与思考强度的来源。默认配置的有效性与启动权限分开显示。见 [Agent 与 subagent](../customization/agents.md#重建会话上下文)。

## 会话控制

### 提示词生效详情

在会话标题栏打开 **⋯ → 提示词生效详情**。抽屉独立于右侧栏，窄屏也能打开，显示当前 Agent 身份、profile、模型与执行器，提示词通道及来源顺序，各字段覆写状态与原因，文件位置和 cognition anchor 的作用域。

绑定与磁盘版本有助于识别改动的来源文件。要真正重新加载会话的提示词来源，请在会话空闲后使用[重建上下文](../customization/agents.md#重建会话上下文)。**检查所有分支**是另一项操作，只查看已配置的共用、主 Agent 与独立 Agent 提示词文件，不切换当前身份。

### 驾驶舱

桌面宽度下，右侧面板标题栏的**标准 / 驾驶舱（Standard / Cockpit）**在常规宽度和加宽并接管预览区之间切换。两种状态下对话与输入框都留在主栏；选**标准**或**退出驾驶舱**会恢复原来的预览内容、标签、草稿和宽度。打开文件、Agent 详情或 Skill 预览同样会退出驾驶舱。

## Usage

从侧栏打开**用量（Usage）**页（`/usage`），只有「历史」「实时」和「外部同步」三个标签，默认打开「历史」：

- **历史（History）：** 某个日期范围的 Token 用量与估算费用，默认为今天。Token 与费用有各自的完整度指示，**Data reliability** 区分未知平台与空区间。已有带筛选的用量链接打开历史页。见[用量统计](./sessions.md#gui-用量统计)。
- **实时（Live）：** 本服务所有会话的原生请求运行数与排队数。展开「请求详情」可看模型、供应商、角色维度，以及排队行的阻塞规则 ID 与等待时间；连接失败时标明最后计数已过期。同一标签内的「并发限制」可新增或编辑规则，选择模型或供应商目标，设置全服务共享或每会话独立的上限。开关可暂停规则，不删除其内容；保存后对新请求与排队请求生效，不终止已在途的流。
- **外部同步（External sync）：** 接收本服务自己用量的目的地，有三种：**vibecafe.ai**、**Kiki webhook** 和**脚本（Script）**。外送的只有模型、UTC 半小时、四项 Token 计数、质量与费用——不含提示词、回复、标题、工作区名或路径。

  **vibecafe.ai** 目的地直接在页面上登录：点**登录 VibeCafe**，用页面给出的码在浏览器里批准，页面会报告结果。这里没有需要复制的授权码，也没有地址、client id 或密钥要填——目的地固定是 `https://vibecafe.ai`。自定义地址、或者你自己提供的密钥属于高级路径。该流程尚未对线上服务实际跑通过：若没有走完，目的地会保持页面当时的状态，并且没有发出任何数据。

**Kiki webhook** 目的地填写你自己的 HTTPS 端点，认证可选 `none`、`bearer` 或 `hmac`，并可开启 gzip。密钥要么存进系统钥匙串，要么由你显式选择存成服务器上的私有文件——钥匙串失败会直接报错，不会悄悄改成文件；私有文件靠文件系统权限保护，并非静态加密。

已有 `/usage?panel=limits` 链接会打开「实时」并定位到并发规则区，不再有单独的「限制」标签。

外部同步无需实验开关；没有目的地时不会发送数据。登录只保存批准的凭据，目的地仍是**停用**状态，也没有给过同意。选目的地、预览确切内容、同意一次，再启用。

没有同意过的目的地不会发送数据。扩大时间范围、更换端点，或凭据换成了另一个身份时需要重新同意，缩小范围或调整周期不需要。暂停保留队列，移除会询问是否丢弃排队数据，请服务方删除它已持有的用量则是另一项操作。升级时，已退休的 `usage_export` 开关若被显式关闭，会将已有目的地暂停一次，保留同意记录与排队数据；需要继续发送时逐个恢复目的地。命令行侧的对应做法见 [`kiki usage-export`](../reference/command.md#kiki-usage-export)。

**脚本**目的地以你自己的 OS 用户和普通权限运行你的命令——它可以自行读取文件或访问网络，这不是沙箱。Kiki 只把不含内容的批次写入它的 stdin，并从输出读取 receipt（回执）。

请求看似卡住时，先打开「实时 → 请求详情」再改上限：排队行会指明本地阻塞规则，供应商 HTTP 429 要看供应商自己的报错；本地队列满、等待超时、立即拒绝需要不同的调整。字段、示例与错误码见 [`request_governance`](../configuration/config-files.md#request-governance)。这些规则管辖的是本服务自己发出的模型请求：当你把一轮交给 Codex、Claude Code 或 Grok Build 当引擎时，那些请求属于引擎自己，不计入这里；而外部工具回过头来让 Kiki 跑原生请求，则照常计入。

## CLI 侧对应

TUI 没有**设置**对话框。终端侧的偏好（主题、编辑器等）在 `tui.toml` 里配置，或用交互命令 `/config`、`/theme`、`/editor`——见 [`tui.toml`](../configuration/config-files.md#tui-toml)。Agent 与运行时设置在 `config.toml`。
