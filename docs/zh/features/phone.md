# 手机会话

手机会话把一个已配对的聊天接到角色的日常会话，或接到你选定的会话。打开 **设置 → 通知与消息**，页面按 **双向对话**、**通知推送** 和 **本机提醒** 分页展示，默认打开 **双向对话**。

粘贴一段配置并检查，或在这一页用微信扫码。微信这条路径不需要令牌，也不需要填写数字编号。账号连接后，直接从 **绑定角色或线程** 选择目标角色或已有会话，开启监听并用手机向该账号发一条消息；Kiki 识别出聊天身份后显示发信人、聊天和一段预览，点击绑定即可生效。已有连接添加新绑定时无需重新扫码或再次粘贴配置。粘贴内容里的聊天编号不会成为绑定。连接处于监听中时，新的手机消息会显示在这一页上。

已绑定的一行可以改到另一个角色或会话，在选项里调整忙碌策略、正文方式、开关手机交互，或重新跟随新绑定的默认。回合正忙时，下一条手机消息可以排队，也可以插入当前回合。手机上可以在回合结束时看到完整可见正文，也可以看到已经写出的正文。多道题会一起保留，直到每一题都有答案。还没处理完的审批和提问，在 Kiki 重启后仍可从手机回答。QQ 和微信上，每个数字回答下一道未完成的题；不是选项里的文字也算在这道题上。要求输入口令的登录留在桌面的 SSH 界面。可见正文还没发完时 Kiki 重启，手机会继续收到剩余部分，这个回合不会重新开始。

QQ 和微信使用完整正文模式，不支持修改已发消息或显示按钮，手机上用选项数字回答。QQ 不能接收文件；通用 OneBot 桥也没有可识别的消息过长错误类别。QQ 拒绝的正文不算已送达，完整回复仍可在桌面查看；Kiki 不会把不明失败当成过长而自动拆分重发。微信因消息过长拒绝时，完整正文会作为一份文件发出。平台不能按语音发送的声音会按原始文件发送，并单独计数。

单向通知通道不变。如果机器人已经设置了 webhook，页面会说明，并保留那个 webhook。

## 留在这台电脑上的内容

令牌存在现有的通知凭据里。它不会写入会话，也不会写入诊断日志。尚未绑定的人发来的消息只被计数，不会开始一个回合。
