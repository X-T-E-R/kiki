# 多空间、远程连接与 SSH

Kiki 跑在哪儿由你决定，它能触达的东西也由你决定。这一页讲四个触达面：位于当前电脑或其他电脑上的**空间**；把两台电脑上的空间按方向连起来、由两边各自批准的**配对**；让一个空间往另一个空间发消息、但不给浏览权的**线程消息**；以及把当前空间开给浏览器或手机应用的**设备接入**。最后是会话内 SSH——唯一一个只是会话自己资源的触达面。

这里没有任何一条要经过别人的服务器中转。会话存在运行 Kiki 的电脑上对应空间的 home 目录下；配对和浏览器链接都是你自己开的门，带着一份你能撤销的凭据。

## 多空间与工作模式 {#空间-你打开的那些个-kiki}

**空间**是一套独立的对话、记忆和工作区。每台电脑默认都有**主空间**，由它管理这台电脑上登记的其他空间。每个空间都可以有自己的快捷方式、窗口行为和凭据范围，工作空间与个人空间并排放在一起，也不必共用登录状态。

凭据是每个子空间自己做的决定。**与主空间共享**表示它复用**主空间**的凭据；**本空间独立**表示它用自己的，在一个子空间登录个人账号不会影响另一个。空间设置详情还会逐项标出这个空间是跟随还是固定，让你看得出某个值是继承来的还是钉死的。SSH 配置可以在空间之间复制，而不用手动搬。

**设置 → 空间与设备 → 空间**列出你可以打开去工作的地方：这台电脑上的空间、其他电脑上已配对的空间、你直接管理的电脑的管理员（SSH）连接档案，以及**当前设备**下的桌面窗口打开方式（**在此窗口切换**或**在新窗口打开**）。**设置 → 空间与设备 → 接入**管理谁能连进当前空间（**设备**、**其他空间**与**外部客户端**）；**设置 → 空间与设备 → 当前设备的连接**展示当前窗口怎样连到服务端。要改子空间的凭据范围，在**设置 → 空间与设备 → 空间**里打开该子空间自己的卡片。对话框其余部分见[设置页导览](/zh/guides/settings)，这些凭据能触达什么见[模型连接、提示词与权限](/zh/features/freedom)。

**工作模式**是空间里的工作入口，不是另一层数据隔离。模式菜单默认提供 Kiki 和 Work；显式设置 `KIKI_EXPERIMENTAL_WORK_PRESETS=false` 或 `[experimental] work_presets = false` 仍可关闭。每个空间分别保存自己的 Work 设置、名称和首选任务。Work 提供 Office、写作、提取与表格检查入口；启用面板显示实际已安装的包，并在安装缺失包或 OfficeCLI 前征求同意。部分安装失败时保留已成功的包，可以重试其余部分。切换模式不改变已有会话的模型、profile 或权限；移除模式也保留文档、会话和共享插件。

桌面上的**在新窗口打开**会在同一空间里打开另一个模式。模式和浏览位置属于各自窗口，空间的服务则共用；关闭一个窗口不会停止后台工作。显式重启或升级会先说明对该空间其他窗口和未完成工作的影响，确认后才取消工作并正常排空。不是由桌面版管理的守护进程，仍需通过它自己的管理入口停止。

## 跨电脑空间配对

配对是从一个空间指向另一台电脑上另一个空间的单向链路。它不是共用登录：目标空间有自己的身份，必须先批准来源，数据才会流过去。出站配对（你从这里打开的其他电脑上的空间）位于**设置 → 空间与设备 → 空间**；入站授权（允许连进当前空间的其他空间与设备）位于**设置 → 空间与设备 → 接入 → 其他空间**。

接收默认关闭。在 GUI 的**设置 → 空间与设备 → 接入 → 其他空间**里点**配对码**，面板会在生成配对码前先写明对方能做什么，并说明生成配对码会开启**允许其他空间连入**，让这台电脑在局域网和 Tailscale 上接受配对，直到你把该开关关掉。**打开这个空间（浏览与对话）**始终包含；**在此空间发送线程消息、启动模型运行和新建会话**默认不勾选，GUI 里只有勾选时才会请求或授予线程消息权限；勾选后明确授予五种线程消息操作。在发起连接的一端，通过空间切换面板或**设置 → 空间与设备 → 空间**里的**配对空间**扫描 `kiki://pair?endpoint=<encoded>&code=<encoded>&fp=<fingerprint>` 二维码，或填入十分钟有效的 `XXXX-XXXX` 配对码，即可兑换每条连接独立的对等凭据，无需共享服务端的全局 `server.token`；配对成功后会留在当前空间，并提供**切换**按钮供你按需进入新空间。配对二维码包含目标电脑公钥的 SHA-256 指纹。Kiki 只接受指纹匹配的证书，然后才发送配对码或对等令牌。

建议的局域网地址仍是 `http://`，因为同一个监听端口也通过 HTTP 为浏览器和手机应用提供服务。目标支持 TLS（用于加密连接的协议）时，空间配对及之后的空间间通信会在该端口使用 TLS。手动输入直连配对码时，Kiki 会先尝试 TLS，并在保存的配对记录中显示首次看到的指纹，供你核对。只有没有固定指纹的手动配对遇到不支持 TLS 的旧目标时，才会退回未加密的 HTTP；已固定指纹的配对绝不会降级。原有未固定指纹的 HTTP 配对仍可使用，但基于配对授权的证明不会加密后续 HTTP 流量，也不能阻止实时转发。浏览器和手机通过 HTTP 连接的限制见[浏览器设备接入](#浏览器设备接入)。

每次已保存连接发送持有者令牌或配对凭据前，Kiki 都会核对目标空间身份，并用一次性随机数证明双方持有配对授权；后台摘要读取也会做相同检查。

同一来源重新配对时，目标空间会撤销该来源此前所有已批准的授权，并关闭使用这些授权的连接。它也只撤销绑定到旧配对授权的线程消息权限，保留单独批准的权限。

Kiki 会保留现有配对记录；未填写新名称时沿用旧名称，并保留后台摘要、共享空间与书签选择。新的配对选择决定是否新建绑定到这次配对的线程消息权限。已批准的配对授权不会自动过期。REST 侧的 `POST /api/remote-connections/pair` 接受可选布尔字段 `requestBridge`（省略时仍默认请求线程消息，兼容旧客户端；传 `false` 则只申请打开空间的权限，手机端与未勾选线程消息的 GUI 配对面板都走这一方式）。

在终端里，`kiki pair` 保持原有默认行为：在目标端运行 `kiki pair` 会开启入站开关、在本机可达的局域网和 Tailscale 网卡上启用直连对等监听，并打印允许线程消息的十分钟配对码；在来源端运行 `kiki pair <endpoint> <code>` 会兑换对等凭据，并请求从当前工作区到目标最近工作区的单向线程消息通道。通过 SSH 连接时，选择主机或输入 `user@host`（或运行 `kiki connections ssh connect --host user@host`），一步完成探测、附着或按需启动远端守护进程、签发独立对等凭据并建立连接；两台电脑只需连接主协议版本一致，Kiki 构建版本与发布通道可以不同。

设置里的每一条配对行都会展示连接状态、最近一次测量值、该空间是否可打开，以及线程消息方向（**双向**、**仅发出**、**仅接收**或**无**）。接入列表还会显示最近一次经过授权的连接时间。只有实际请求通过配对授权认证后才会更新这个时间；无效凭据和仅握手验证不会更新。服务端按 5 分钟间隔保存活动时间，并在正常关闭时保存最新记录。已批准、没有活动租约、连续 30 天没有使用的授权会显示闲置提示，并在点击撤销时要求确认；授权不会因此自动过期。每行菜单里的**线程消息…**可以单独关闭或撤销已有的线程消息权限，而不必移除整条配对，同时保留单条连接的启用、停用、重试与移除操作。在目标端撤销某次配对授权（`inbound revoke <grantId>`）会同时停掉该对端的浏览、事件流以及随该次配对创建的线程消息权限，不影响其他已批准来源或单独审批的权限；`inbound disable` 关闭全部对等访问，但保留允许列表。移除出站配对只释放本地凭据和自有隧道，不会停止远端守护进程，也不会撤销已在对面启动的工作。离线的空间保留最近一次测量值和时间戳，而不是报一个编出来的零。

需要脚本化或分步控制时，仍可使用显式邀请与 SSH 规划命令：`inbound invite` 为已知来源身份签发一次性邀请；用邀请新增连接时，Kiki 会先证明邀请有效并核对目标身份，再发送所有者令牌。`ssh plan` 只查询远端电脑状态而不做改动，`ssh execute PLAN_ID` 执行挂接（仅在显式传入 `--ensure` 时启动远端守护进程）。Kiki 不会替你往远端安装软件。

目标电脑暂时不可达时，手机应用会自动重连，已打开的会话和草稿留在原处；也可以就地重试或切换电脑。若目标关掉了**允许其他空间连入**，等所有者重新开启后，普通读取会自动恢复。某一次操作被拒绝不会把整条连接判成退出登录，Kiki 也不会自动重发被拒绝或结果未知的写入。令牌失效或授权被撤销时，请重新配对或更新连接授权后再试。

见 [`kiki pair`](/zh/reference/command#kiki-pair)、[`kiki connections`](/zh/reference/command#kiki-pair) 和 [`kiki bridges`](/zh/reference/command#kiki-bridges)。

## 线程消息

线程消息通过两个空间之间的单向权限传递（终端管理命令为 `kiki bridges`，HTTP 管理路径为 `/api/thread-bridges`）。一个桥接权限有五种操作：`read` 读取线程，`send` 排入消息，`wait` 等待活动，`wake` 允许发出的消息在接收端启动一轮模型运行，`create` 在目标工作区的规范根目录创建新的顶层会话。隐式配对权限及其自动创建的反向权限默认都只有 `read`、`send` 和 `wait`；`wake` 与 `create` 只有明确授予时才会包含。没有 `wake` 时，发出的消息会保持挂起，直到有人打开或运行该线程。在 GUI 生成配对码时勾选**在此空间发送线程消息、启动模型运行和新建会话**，会明确授予五种操作。桥接授权覆盖整个目标工作区并包含 `create` 时，`ThreadCreate` 会返回可直接传给 `ThreadSend`、`ThreadRead` 或 `ThreadWait` 的线程引用。新会话的权限上限是 `auto`；跨空间创建不能设置 `cwd` 或 `from_subagent`。你也可以单独审批范围更窄的独立权限，精确指定来源与目标范围、操作集合和过期时间。

独立的线程消息权限永远不授予打开和浏览空间的权限；在设置里，仅带线程消息的连接会标明**不可打开**，不显示**切换**按钮。你可以在**设置 → 空间与设备 → 空间**或**接入 → 其他空间**的配对行菜单里打开**线程消息…**，单独撤销入站或出站的线程消息权限；撤销配对授权本身则会一并撤销随该次配对创建的线程消息权限，同时保留单独审批的其他权限。回执区分来源挂起、目标已接受、提示已送达和被拒绝——送达指的是提示到了，不是模型回话了。挂起的发送重试时保留原来的键和顺序，`retry` 检查的是持久队列，而不是新建一条消息。撤销线程消息不会删除任何会话。

见 [`kiki bridges`](/zh/reference/command#kiki-bridges)。

## 浏览器设备接入

Web 访问把**当前**空间开给另一台设备上的浏览器。拿到链接的人可以完整使用这个空间，权限和你一样——这不是只读分享，临时入口临时的也只是它开着的时间。

在**设置 → 空间与设备 → 接入 → 设备**里开启，或者在终端用 `kiki web --temporary`（默认，开八小时然后自己关掉）、`kiki web --persistent`（一直开着到你关掉）。`kiki web` 在共享守护进程上开门，必要时先启动守护进程，命令本身随即返回，不占着终端。每次运行会打印一条一次性链接，十分钟内有效，把一个浏览器签进来；Kiki 把它兑换成浏览器自己持有的会话 cookie，服务端只留摘要，链接只显示一次——丢了或用过了就换一条新的，而不是去查。每台新设备都要新链接；GUI 里是**为另一台设备生成链接**。`kiki web --revoke [session-id]` 登出一个或全部浏览器。关掉 Web 访问会撤销所有链接和所有浏览器会话，但不会停掉守护进程、桌面应用或 TUI，也不会取消已经启动的活。

浏览器和手机通过局域网直连监听器访问时使用明文 HTTP；同一网络里的任何人都能读到发出去的内容。`--insecure-no-tls` 也会通过 HTTP 提供未加密的服务。空间配对使用的 TLS 不会保护这两种 HTTP 请求。在你信任的网络之外使用，请在前面放一个终止 TLS 的反向代理，并传入 `--public-url <https://…>`。

Web 访问和空间配对是两种不同的对象。另一台电脑上已配对的空间有它自己的身份和一份由你逐个批准的来源授权；浏览器链接是对当前空间的设备接入权限，归这台电脑的所有者。打开 Web 访问不会放任何其他空间进来，已登录的浏览器也只能切换到你在**设备**标签下明确勾选共享的已配对空间。

见[在浏览器里使用 Kiki](/zh/server/local-server#在浏览器里使用-kiki)。

## 会话内 SSH

会话可以持有 SSH 主机。用输入框的 **+** 菜单加入，输入框上方的 **SSH** 控件会显示已加入主机的数量并逐台列出，点 **X** 移出；点 **SSH** 本身会打开这个会话的主机面板，每台主机一行，带**已启用 / 未启用**开关和它自己的连接状态，可以在这里增减。加入超过三台时，这一行默认折叠，点**展开全部 (n)** 才逐台列出，输入框不会被主机挤占。已加入的主机是会话的资源，不会随每条消息重复携带——所以时间线不会堆满主机气泡，移除主机也只影响这个会话，不动你电脑上的配置。

这个控件只在会话已经持有主机时出现。一个还没加入任何主机的会话，输入框上方不会有 SSH 这一行，**+** 菜单仍然是加入第一台主机的入口。主机还在，控件就一直留着，轮次之间也在——因为「已加入」是会话自己的状态，跟此刻有没有请求在跑无关。

加入主机是把它放进会话上下文，并不会立即连接。新会话里，在 **+** 菜单选中主机后，第一条消息发出前就会显示同一个 **SSH** 控件；你选的主机会在那条消息发出前加入创建好的会话。

Agent 也可以在工具调用里直接指定已配置的主机，不必先手动加入。主 Agent 和 subagent 都走同一连接批准流程；隐藏主机、拒绝请求、主机密钥校验和文件权限规则仍然生效。从上下文移出主机，不等于撤销已经批准的连接。

文件路径属于选中的主机。在 Windows SSH 主机上，使用 `E:/work/result.log` 这样的绝对路径；`Read`、`Write` 和 `Edit` 通过 SFTP（SSH 文件传输）操作，`Bash`、`Glob` 和 `Grep` 使用那台主机的 PowerShell，命令要写 PowerShell 语法，远端不需要安装 Git Bash。远端命令失败时会如实报错，而不是返回空结果。
