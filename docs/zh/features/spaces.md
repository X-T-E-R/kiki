# 数据与机器都在你手上

Kiki 跑在哪儿由你决定，它能触达的东西也由你决定。这一页讲四个触达面：**空间**，也就是你打开的那些个 Kiki；**远端连接**，把一个 Kiki 按方向指向另一个，两边各自审批；**thread bridge**，让一个 Kiki 往另一个发消息，但不给它浏览权；还有 **Web 访问**，把这个 Kiki 开到浏览器里。最后是会话内 SSH——唯一一个只是会话自己资源的触达面。

这里没有任何一条要经过别人的服务器中转。会话存在服务端所在机器的 Kiki home 下；远端连接和网页链接都是你自己开的门，带着一份你能撤销的凭据。

## 空间：你打开的那些个 Kiki

**空间**就是你在用的某一个 Kiki。主空间管着这张列表，各个空间才是你真正打开的。每一个都可以有自己的快捷方式、自己的窗口行为和自己的凭据范围，所以工作的 Kiki 和个人的 Kiki 可以并排放着，而不必共享能登录的东西。

凭据是每个子空间自己做的决定。**与主空间共享**表示它复用主空间的凭据；**本空间独立**表示它用自己的，在一个子空间登录个人账号不会影响另一个。空间设置详情还会逐项标出这个空间是跟随还是固定，让你看得出某个值是继承来的还是钉死的。SSH 配置可以在空间之间复制，而不用手动搬。

在**设置 → 空间**里，于子空间自己的卡片上改凭据范围。这一页其余设置见[设置页导览](/zh/guides/settings)，这些凭据能触达什么见[每一层都归你](/zh/features/freedom)。

## 远端连接：一个 Kiki 指向另一个

远端连接是从这个 Kiki 的 home 指向另一台机器上另一个 Kiki home 的单向链路。它不是共用登录：目标有它自己的身份，而且必须先批准来源，才有东西能流过去。

接收默认关闭。在目标上打开这个开关本身不批准任何人——你还要生成一个邀请，交给来源，来源再据此注册一条连接。每条连接是列表里的一行，带着自己的状态、最近一次的测量值，以及只影响这一条链路的动作：启用、停用、重试、移除。`inbound revoke <grantId>` 停掉某一个来源的读取和流，不影响其他已批准的来源；`inbound disable` 关闭全部对等访问，但保留允许列表。移除一条连接会释放本地凭据和它自己建立的隧道，但不会停掉目标守护进程，也不会撤销它已经启动的活。目标离线时保留的是最近一次的测量值和它的时间戳，而不是报一个编出来的零。

命令这一侧先规划后执行。`kiki connections ... ssh plan` 只做查询；`ssh execute PLAN_ID` 才会挂接；只有显式的 `--ensure` 才可能启动远端守护进程，而且它会一直跑到你停掉为止。两者都不会顺带打开入站访问。GUI 挂接已运行的目标时也会重新查询，但不会启动它，也不多问一次确认。两端需要兼容的连接协议，以及能用的 SSH 认证和 known-host 校验；Kiki 的版本字符串不必完全相同。Kiki 不会替你往远端装东西。

如果目标暂时关闭入站访问，等所有者重新打开后，再尝试你的操作即可。某一个操作被拒绝，不会把整条连接判成未登录，Kiki 也不会自动重发被拒绝的写入。令牌失效或授权被撤销仍会拒绝访问；请先更新连接的凭据或授权，再尝试。

见 [`kiki connections`](/zh/reference/command#kiki-connections)。

## Thread bridge：能说话，不能浏览

Thread bridge 是两个 home 之间传线程消息的单向通道。它比远端连接窄得多，这是有意的：目标 home 批准的正是确切的来源与目标范围、确切的操作——`read`、`send`、`wait`，以及你明确要求的 `wake`——和一个过期时间，桥只带这些，别的一概不带。没有 `wake`，发送就保持挂起，不会真的在对面启动一轮模型。

桥永远不授予 GUI 浏览权限，GUI 令牌和 SSH 登录也不授予桥权限。回执区分来源挂起、目标已接受、提示已送达和被拒绝——送达指的是提示到了，不是模型回话了。挂起的发送重试时保留原来的键和顺序，`retry` 检查的是持久队列，而不是新建一条消息。撤销桥不会删除任何会话。

见 [`kiki bridges`](/zh/reference/command#kiki-bridges)。

## Web 访问：把这个 Kiki 开到浏览器

Web 访问把**这个** Kiki 开给另一台设备上的浏览器。拿到链接的人可以完整使用它，权限和你一样——这不是只读分享，临时入口临时的也只是它开着的时间。

在**设置 → 空间 → Web 访问**里打开，或者在命令行用 `kiki web --temporary`（开八小时然后自己关掉）、`kiki web --persistent`（一直开着到你关掉）。每次运行会打印一条一次性链接，把一个浏览器签进来；Kiki 把它兑换成浏览器自己持有的会话 cookie，服务端只留摘要，链接只显示一次——丢了就换一条新的，而不是去查。每台新设备都要新链接。`kiki web --revoke [session-id]` 登出一个或全部浏览器。关掉 Web 访问会撤销所有链接和所有浏览器会话，但不会停掉守护进程、桌面应用或 TUI，也不会取消已经启动的活。

明文局域网 HTTP（`--insecure-no-tls`）不加密：同一网络里的任何人能读到发出去的内容。在你信任的网络之外使用，请在前面放一个终止 TLS 的反向代理，并传入 `--public-url <https://…>`。

Web 访问和远端连接是两个不同的对象。远端 Kiki 是另一个 Kiki，有它自己的身份和一份由你逐个批准的来源授权；网页链接是对这一个的访问权，归这台机器的所有者。打开 Web 访问不会引入任何一个 Kiki。

见[在浏览器里使用 Kiki](/zh/server/local-server#在浏览器里使用-kiki)。

## 会话内 SSH

会话可以持有 SSH 主机。用输入框的 **+** 菜单加入，输入框上方的**SSH**控件会列出已加入的主机，点 **X** 移出，也可以从这一行重新打开同一个列表增减。已加入的主机是会话的资源，不会随每条消息重复携带——所以时间线不会堆满主机气泡，移除主机也只影响这个会话，不动你机器上的东西。

这个控件只在会话已经持有主机时出现。一个还没加入任何主机的会话，输入框上方不会有 SSH 这一行，**+** 菜单仍然是加入第一台主机的入口。主机还在，控件就一直留着，轮次之间也在——因为「已加入」是会话自己的状态，跟此刻有没有请求在跑无关。

加入主机只是让会话可以用它，并不会立即连接。新会话里，在**+** 菜单选中主机后，第一条消息发出前就会显示同一个**SSH**控件；你选的主机会在那条消息发出前加入创建好的会话。

![输入框上方的 SSH 面板：列出已加入这个会话的主机，以及还可以添加的主机。](/shots/spaces/ps-20261005-spaces-session-ssh.zh.png)

见[界面导览](/zh/guides/interface#输入框)。
