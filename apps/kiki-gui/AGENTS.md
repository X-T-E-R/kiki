# Kiki GUI Agent Guide

- Kiki GUI visual acceptance uses the headless proof runner by default; it never depends on an Ego Lite or desktop window. Use `node apps/kiki-gui/scripts/visual-proof.mjs --config apps/kiki-gui/scripts/visual-proof-headless-smoke.mjs` for the checked-in smoke matrix, or pass `--base-url <url> --token <token> --route <name=/path> --theme light,dark --locale en,zh --viewport wide,narrow` for an existing GUI server. Omit `--base-url` and add `--scenario <fixture> --vite` to start and clean up Vite plus the fixture server automatically.
- Use Ego Lite / a desktop browser only for a third-party site that needs the user's login state or a real desktop WebView. If an Ego capture is unavoidable, restore an agent-owned target before the screenshot with `Browser.getWindowForTarget` and `Browser.setWindowBounds({ windowState: 'normal' })` (for example: `const { windowId } = await task.cdp('Browser.getWindowForTarget', { targetId: page.targetId }); await task.cdp('Browser.setWindowBounds', { windowId, bounds: { windowState: 'normal' } });`). Never touch another user's TaskSpace. Real desktop executable acceptance follows the `kiki-desktop-ops` process.
- Reuse `src/components/message/EditUserRow.tsx` across transcript views and `src/test/connectedTranscriptFixture.tsx` in editor interaction tests.

## 4-Zone Shell, `h-12` Datum & Subtraction-First `<Composer />` Standard

1. **Zone 1 — Sidebar `18px` Keyline & Two-Tier Bell**: `Sidebar.tsx` and `SpaceSwitcher.tsx` align on a single `18px` vertical left keyline (`pl-[18px] pr-2.5` header row; `px-2.5` outer + `px-2` row + uniform `w-5` leading icon slot across all lower sections). `+ 新会话` is a flat rail row aligned on the `18px` keyline with a `20×20` `rounded-full bg-accent/12 text-accent-ink` circular `+` icon. The activity bell uses a two-tier inset signal: `needsYou.length > 0` displays an inset `bg-attention` count (`top-1 right-1`), while finished unread runs with `needsYou === 0` show a quiet `7px` inset dot (`bg-ink-soft/65`) with zero numeric text (`data-activity-badge={inbox.total}` preserved).
2. **Zone 2 — Continuous 3-Pane `h-12` (`48px`) Header & `AgentFamilyPopover`**: `WorkspaceHeader` is always single-row `h-12` with `border-b border-hairline/70`. `AgentWorkspaceHeader` renders inline ancestor crumbs + a single `<h1>` leaf trigger opening `@base-ui/react` `AgentFamilyPopover` (Parent / Children / filtered Siblings in both `showBreadcrumb=true` and `showBreadcrumb=false` modes), with inline running-children `● N` pill, quiet branch seam badge, and `[合回主线]` (`data-branch-fold-action`) on the right (no duplicate `<h1>`, no header `model·effort`, no `data-agent-relations-surface`, no floating `data-branch-fold-bar` above `<Composer />`).
3. **Zone 3 — Right Inspector `h-12` Hairline Tabs (`运行 | 配置`)**: `[data-rail-pinned]` is strictly `h-12`. When matching center (`sameAsCenter`), `[data-rail-owner]` renders two hairline bottom-border text tabs (`运行` / `Run` `[data-rail-tab="run"]` and `配置` / `Config` `[data-rail-tab="config"]`, active `1.5px` `bg-ink` indicator, quiet `5px` `bg-attention` dot on `配置` only when actionable config attention such as a persona update exists) alongside a visually hidden `<h2 tabIndex={-1} data-rail-owner-heading>` for focus management, with `[data-rail-pending-jump]` (`● N`) and `[data-rail-close]` (`×`) on the right. When peeking a subagent (`!sameAsCenter`), `h-12` renders `RailCrumbs` and a compact `h-8` sticky hairline tab strip (`[data-rail-sub-tabs]`) sits directly beneath it. Cockpit mode is removed (`useRailMode()` stays as a fixed `'default'` seam in `shell.tsx`). Inside `运行`, `NeedsYouList`, `ProfileHead` + `InspectorNow`, compact `用量` (caption metrics in hover/aria tooltips), `会话分叉`, `待办` (`RailTodos` clamped to `line-clamp-2` + `AgentPlanSection`), active running `后台任务` (only when running > 0), `智能体`, and a bottom quiet history fold group (`工作笔记`, settled `后台任务`, `动态`, `沟通`) scroll smoothly inside `.rail-page`. Inside `配置`, active work surfaces in a compact SVG `RailLiveTopology` strip (`0px` when idle), followed on main sessions by unfolded direct controls (`系统能力`, `会话插件` with disabled > 2 folded, `MCP`, `通信信道`, `定时任务`, `角色设定`) and folded agent foundation rows (`自动规则`, `能力`, and main-only `会话`). Thinking effort labels share `formatThinkingEffort(effort, t)` (`src/lib/thinkingEffort.ts`).
4. **Zone 4 — Subtraction-First `<Composer />` (`2–3 Rows Max Inside Card`)**:
   - Card interior (`[data-composer-body]`) holds at most 3 rows: (1) optional transient edit banner (`queueEditing`) or a single-row `44px` (`h-11`) horizontal scroll shelf (`[data-context-tray]` -> `[data-context-shelf]` with `pt-2 pb-1` headroom so corner `×` badges never clip), (2) unobstructed `<ComposerInput />` (rendering unresolved `[[thread:...]]` / `[[room:...]]` inline as humanized `@Thread · <short>` pills), (3) calm bottom toolbar (`[data-composer-toolbar]` — single `Stop` when `busy && !canSend`, explicit `[↑ | ▾]` split Send/Timing when `busy && canSend`, `<480px` `CompactModelSheet`).
   - Mode lives in one place (`RunModeChip` + `data-run-mode` ring + placeholder; no `data-goal-armed` top banner).
   - Plugin panels live exclusively in the top-right header `WorkspacePanelsControl` (`SessionView`, `AgentWorkspace`, `NewSessionPage`) + `/` slash completion — never duplicated inside `<Composer />`, `+` (`AddMenu`), or the Right Rail tail. When `panelSlots.length <= 4`, `WorkspacePanelsControl` renders each `open_plugin_panel` slot directly inline as a 1-click button (icon + `hidden xl:inline` label, per-plugin quiet `bg-ink-soft` active indicator, `bg-canvas text-ink` active tab toggle), overflowing beyond 4 into `Popover` (`data-workspace-panels-trigger`), with `[预览]` (`data-preview-toggle`) as a separate independent button when `tabCount > 0`.
   - Right Rail separates read-only `能力` (`CapabilitiesBlock`: tools / skills / subagents, lazy-fetched on open) from unfolded direct session switches in `配置` (`SessionEnvironmentControls`: system capabilities, session plugins with disabled > 2 folded, session MCP), strictly scoped to `MAIN_AGENT_ID` for session-wide controls.
   - Resident SSH hosts (`[data-composer-ssh-strip]`) and active `<PluginStatusCapsules />` live in the bare external `[data-composer-status-line]` below the card (`>_ host +N ▾` opening upward via `@base-ui/react` `Popover` `side="top"`).
