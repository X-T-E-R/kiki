# 特色聚焦：任务看板 —— 看得见、指得着的工作

*Kiki 特色宣传页。这些页面是 README 之外的宣传配套，描述的均为已发布的行为。*

聊天记录是讨论工作的地方，却是安放工作的糟糕场所——往回滚得够远，每个决定都会溶解在对话里。Kiki 给每个工作区配了一块**任务看板**：桌面 UI 里的看板面板，把需求和任务当作一等公民的对象来跟踪，而不是一条条消息。

![工作区任务看板：需求卡片按状态分列，每张卡可关联到正在处理它的会话。](shots/r04-task-board.zh.light.png)

*示例场景；由真实 Kiki 界面渲染。*

## 任务关联会话

看板上的每张卡片都可以关联到正在处理它的会话。看板不是 agent 读过一次就忘的被动待办清单——它是你和机队之间的共享状态。你不仅能看到*什么*还没做，还能看到*谁*在做，并且一键跳进那个会话去纠偏。

## 为什么需要一块看板？

因为多智能体把工作量的记账问题也成倍放大了。一个 agent 一个任务，你脑子记得住。一个主 agent 带着三个子代理、一个后台任务、再加一个 cron 定时跟进——"等等，它刚才在干嘛来着？"就开始烧你的会话了。看板就是答案：一个始终可见、按工作区组织的承诺清单，压缩、重启、上下文窗口都奈何不了它。

配合[目标模式](https://x-t-e-r.github.io/kiki/zh/)（跨轮次持续推进的客观目标）、cron 定时注入和实时 agent 面板，看板补上了闭环的最后一块：**决定**工作、**看着**工作、**回到**工作——三个不同的场景，各有一件趁手的工具。
