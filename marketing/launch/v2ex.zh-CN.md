# V2EX（分享创造）草稿

**节点：** 分享创造

**标题：** 开源本地 AI 智能体工作台 Kiki：一个主会话按角色混编不同模型，提示词细到单个工具描述都能按模型覆写

**正文：**

Kiki 是一个开源（MIT）的本地 AI 智能体工作台，桌面应用、终端（`kiki`）和浏览器（`kiki web`）共用同一个本地守护进程：https://github.com/X-T-E-R/kiki

它要解决的是两件事：一是稍微复杂一点的活（梳理和修改代码库、核对一摞本地 PDF 与表格、写长文报告）塞在单窗口里由一个模型干到底，既慢又容易淹没上下文；二是智能体底下的角色定义、模型绑定和内置提示词应该能直接打开改，而不是焊死在黑盒里。

目前主要提供这几块能力：

- **按角色混编不同厂商的模型。** 主智能体负责拆解任务与验收，通过 `AgentRun` 派出上下文隔离的子智能体：比如只读探查用快模型、实现或初稿用 DeepSeek / GLM、独立审查换另一家厂商。子智能体如果没有绑定模型且未配默认模型，派发会直接报 `model.not_configured`，不会静默回退去烧主会话的贵模型。每个子智能体都有独立记录，随时可以点开看，也能直接给它发消息。
- **角色就是纯文本 Markdown。** 每个 Agent Profile 是一份 Markdown，frontmatter 写模型、思考档位、工具白名单和允许派发的子角色，正文就是系统提示词。保存后新派发的子智能体会直接用上新内容；已经在跑的会话保留启动时的快照，点「重建上下文」就能在不丢对话的前提下刷新。别的工具写的 agent 文件不能直接照搬：frontmatter 字段集合是封闭的，未识别字段会在加载时报错并点名，迁移办法见[文档](https://x-t-e-r.github.io/kiki/zh/customization/agents-and-subagents#agent-文件格式)。
- **提示词细到单个工具描述都能按模型覆写。** 便宜模型翻车往往不是因为不会推理，而是看不懂某个内置工具的说明、乱传参数。Kiki 支持按「全局 → 模型 → 智能体」覆写内置提示词的任意具名字段（比如只针对某个模型重写 `tool.web-search.description`），改完跑 `kiki prompt-fields explain <字段> --model <别名>` 就能核对最终生效文本和来源链。
- **长线任务与忙时队列。** 耗时命令和子智能体在后台跑，结束自动通知主智能体，不用轮询。智能体忙的时候你发的消息会进队列，每条消息可以单独选「空闲后 / 子智能体完成后 / 任务完成后」送达。配合 `/goal` 跨轮次目标、可逐条撤销的分层记忆（全局 / 工作区 / 角色），以及可选的 `kiki-task-board` 工作区需求看板插件，换了会话也知道还剩什么没干完。人不在电脑前时，还能在设置里用微信扫码或配 QQ 绑到角色或会话，在手机上回消息、批权限。
- **不止写代码，按需装插件扩展。** 会话、历史和配置留在本机的 Kiki home 里，项目文件夹就在原处，模型请求只发往你自己连接的供应商或本地服务。任务走出纯文本时，按需从目录安装：把本地 PDF/Office/HTML 转成可读 Markdown 的 `Kiki Extract`（处理 PDF 与 Office 需本机备好 Python + MarkItDown）、在本机创建和编辑 Word/Excel/PowerPoint 的 `Kiki Office Suite`、在本机核对 CSV 两表差异的 `Kiki Work`、`Kiki Writing`、`Kiki Notion`、`Kiki Media`，以及 `Kimi Datasource`（需 Kimi Code OAuth 登录与套餐额度）和 `Kimi Browser Extension`（需安装配套浏览器扩展）。浏览器控制本身是系统能力：除了 Kimi 扩展，也可以让 Kiki 自己跑一个浏览器，或用 CDP 接一个现成的。

说明与限制：当前处于 0.x（公开版本 0.4.1），细节还在打磨；macOS 安装包未签名也未公证；Windows 首次运行需先装 Git for Windows；npm 安装需 Node.js 24.22.1+ 或 26.12.1+。仓库里的截图由真实界面渲染的示例场景，不代表性能跑分。项目最初 fork 自 Kimi Code，现独立开发。
