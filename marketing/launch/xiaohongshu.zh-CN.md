## 正文

让贵的模型只干它擅长的那一步。一件事，几家模型分工做，你的智能体，你说了算。

Kiki 是我做的开源（MIT）本地智能体工作台，作为服务跑在自己电脑上，桌面、终端、浏览器和手机看到的是同一场工作。

平时写代码或改跨文件工程，一个主会话把活拆给几个不同模型的帮手：强模型负责想清楚方案和最后验收，便宜的 DeepSeek 或快模型跑探索和局部改动，审查再换另一家模型，省得自己审自己。

而且每个模型都有自己的专武。配方（Recipe）把可复用的提示词、模型设置和可选脚本 Hook 打包在一起，装一次绑在一个模型上，每个绑定可以单独调开关。每个模型就像一个性格不同的孩子，我也算哄好了好几个脾气各异的模型——比如我在公开仓库 `kiki-recipes` 发布了五套（GPT-6.1 Sol、GPT-6 Astra、DeepSeek V4.1、Gemini 4 Argon、Gemini 3.8 Flash），有的要先推演机理和反例再动手，有的要先锚定一份样板。Recipe 只管 Kiki 原生跑的模型，不管 Claude Code 或 Codex 当外部执行器跑的回合。

平时用起来顺手的几点：
- 活丢到后台，跑完主会话自己会收到通知，不用盯着
- 它忙的时候也能发消息进队列，每条可以选空闲后、子代理完成后或任务完成后再发
- 每个智能体就是一份 Markdown，以前在 Claude Code 或 Codex 里的对话也能导进来接着聊
- 需要时再装插件拆本地 PDF、核对表格、用需求看板，或者绑微信在手机上回消息、批权限

工作文件留在原来的文件夹，会话、历史和配置存在自己电脑的 Kiki home 里，模型请求只发往你自己连接的供应商或本地服务。目前还是 `0.x`（`0.5.1`）早期版本，有毛刺很正常；macOS 包未签名，Windows 需要 Git for Windows。

GitHub 搜 `X-T-E-R/kiki`（配方仓库 `X-T-E-R/kiki-recipes`）。
