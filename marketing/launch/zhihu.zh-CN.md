先交代背景：我在做一个开源的本地 AI 智能体工作台，叫 Kiki（MIT，https://github.com/X-T-E-R/kiki）。这篇不是软文式的功能介绍，而是讲我每天实际怎么用它，包括哪里还不好用。

## 一、为什么不用一个模型干到底

长任务里，大部分 token 花在读文件、搜代码、改机械的东西上。这些活强模型能干，但没必要。我更想要的是：强模型负责想清楚要干什么、最后验收，杂活交给便宜模型，审查换一家厂商，免得自己审自己。

问题是大部分工具要么只绑一家模型，要么换模型得整个会话一起换。

## 二、我的分工

在 Kiki 里，每个智能体就是一份 Markdown 文件：frontmatter 写工具、模型、能派发谁，正文是系统提示词。我原来给 Claude Code 写的 agent 文件，直接放进来就能用。

我现在大致这么分：

| 角色 | 模型 | 干什么 |
| --- | --- | --- |
| 主会话 | 海外强模型 | 拆任务、派活、验收 |
| 实现 | DeepSeek | 范围清楚的改动、跑检查 |
| 探查 | GLM | 只读：搜代码、读文档、回事实 |
| 审查 | 另一家厂商 | 只读，独立看结论 |

每个角色在 frontmatter 里写 `model_alias`。有个细节我很在意：子智能体没绑模型会直接报错，不会悄悄继承主会话那个贵模型。

## 三、便宜模型最常见的问题：用错工具

实际用下来，便宜模型最常翻车的地方不是写代码，而是看不懂某个工具该怎么用：参数乱填、该用 A 用了 B。

Kiki 允许覆写内置提示词的任意字段，细到单个工具的描述，而且可以只对某个模型生效。所以我的做法是：哪个模型在哪个工具上老出错，就只给它改那一个工具的描述，写得更短、更直白，别的模型不受影响。

```toml
[models.deepseek.prompt_overrides]
files = ["prompt/deepseek.toml"]
```

改完用 `kiki prompt-fields explain <字段> --model deepseek` 看最终生效的值和来源链，确认它真的收到了我写的那版。

（配图：d02 提示词字段覆写）

这是我觉得最有用、也最少见的一块。多智能体、多模型这些别的工具也有，我不说它独有。

## 四、一跑好几个小时，我怎么不用盯着

1. **后台任务和自动通知。** 主智能体把耗时的线丢到后台，跑完结果自动回到它手里，它不用反复查，我也不用。
2. **边跑边说话。** 它忙的时候我想补一句需求，消息会进队列，每条可以选「空闲后 / 子代理完成后 / 任务完成后」再发，不会半路打断正在干的活。
3. **看板。** 需求写在工作区的需求看板上，智能体自己能读能改。会话关了、换了，需求还在。
4. **挂了怎么办。** 某条线失败了，主会话会收到结果，重新派一条接着干。这部分请看文末的真实录屏，我不在这里夸大。

## 五、还不好的地方

- 还在 0.x，毛刺不少。
- macOS 包未签名；Windows 要先装 Git for Windows。
- 我没做过任何跑分，上面的分工只是我的习惯，不代表哪个模型组合更好。
- 项目最初 fork 自 Kimi Code，现在独立开发；TUI 基于 pi-tui。
