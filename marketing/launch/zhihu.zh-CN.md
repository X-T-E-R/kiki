---

先交代背景：Kiki 是一个开源的本地 AI 智能体工作台（MIT，https://github.com/X-T-E-R/kiki）。这篇不是软文式的功能介绍，而是讲这套工具怎么用，包括哪里还不好用。

## 一、为什么不用一个模型干到底

长任务里，大部分 token 花在读文件、搜代码、改机械的东西上。这些活强模型能干，但没必要。更想要的是：强模型负责想清楚要干什么、最后验收，杂活交给便宜模型，审查换一家厂商，免得自己审自己。

问题是大部分工具要么只绑一家模型，要么换模型得整个会话一起换。

## 二、我的分工

在 Kiki 里，每个智能体就是一份 Markdown 文件：frontmatter 写工具、模型、能派发谁，正文是系统提示词。保存后，下一次派发的子智能体就会用上新内容；已经在跑的会话保留启动时的快照，点「重建上下文」才换成新提示词——这一点和很多人的直觉不一样，改完文件不会当场生效。

我大致这么分：

| 角色 | 模型 | 干什么 |
| --- | --- | --- |
| 主会话 | 海外强模型 | 拆任务、派活、验收 |
| 实现 | DeepSeek | 范围清楚的改动、跑检查 |
| 探查 | GLM | 只读：搜代码、读文档、回事实 |
| 审查 | 另一家厂商 | 只读，独立看结论 |

每个角色在 frontmatter 里写 `model_alias`。有个细节我很在意：子智能体没绑模型、也没配默认模型时会直接报错，不会悄悄继承主会话那个贵模型。

从别的工具搬 agent 文件过来要改一下。Kiki 的 frontmatter 字段集合是封闭的，未识别字段会在加载时报错并点名：外部文件里的 `model` 要换成 `model_alias`；`mode` 这种字段没有对应物，它不是模型别名，含义得自己判断是落到权限模式还是工具设置上。反过来，原来在 Claude Code、Codex 或 OpenCode 里的对话历史可以直接导成 Kiki 会话接着聊，也可以只要一份只读归档，导入前的预览会写明哪些东西留不下来。

（配图：r05 多模型派发树，中文版，标注「示例画面」）

日常分工也不止改代码。同一套派发方式可以拿来拆读本地 PDF、核对表格、写报告：拆 PDF 和 Office 文档装 `Kiki Extract`（处理这些格式需要本机备好 Python 与 MarkItDown），表格键值核对用 `Kiki Work`（本机跑，不改原文件、不上传），写长文可以开 `Kiki Writing` 的手稿面板。

## 三、便宜模型最常见的问题：用错工具

实际用下来，便宜模型最常翻车的地方不是写代码，而是看不懂某个工具该怎么用：参数乱填、该用 A 用了 B。

Kiki 允许覆写内置提示词的任意字段，细到单个工具的描述，而且可以只对某个模型生效。所以比较省事的做法是：哪个模型在哪个工具上老出错，就只给它改那一个工具的描述，写得更短、更直白，别的模型不受影响。

```toml
[models.deepseek.prompt_overrides]
files = ["prompt/deepseek.toml"]
```

改完用 `kiki prompt-fields explain <字段> --model deepseek` 看最终生效的值和来源链，确认它真的收到了你写的那版。

（配图：d02 提示词字段覆写）

这是我觉得最有用、也最少见的一块。多智能体、多模型这些别的工具也有，我不说它独有。

## 四、一跑好几个小时，我怎么不用盯着

1. **后台任务和自动通知。** 主智能体把耗时的线丢到后台，跑完结果自动回到它手里，它不用反复查，我也不用。
2. **边跑边说话。** 它忙的时候想补一句需求，消息会进队列，每条可以选「空闲后 / 子代理完成后 / 任务完成后」再发，不会半路打断正在干的活。
3. **看板。** 需求写在工作区的需求看板上，智能体自己能读能改。会话关了、换了，需求还在。看板是可选的官方插件 `kiki-task-board`，要先装。
4. **定时任务有个前提。** 按 cron 触发的提示词只在还有 Kiki 进程持有那个已打开的会话时才会跑，不是关掉一切也能在后台醒过来。
5. **挂了怎么办。** 某条线失败了，主会话会收到结果，重新派一条接着干。我不在这里夸大，录屏里没发生的就不写。

## 五、还不好的地方

- 还在 0.x，毛刺不少。
- macOS 包未签名；Windows 要先装 Git for Windows；npm 安装要求 Node.js 24.22.1+ 或 26.12.1+。
- 我没做过任何跑分，上面的分工只是习惯，不代表哪个模型组合更好。
- 项目最初 fork 自 Kimi Code，现在独立开发；TUI 基于 pi-tui。
