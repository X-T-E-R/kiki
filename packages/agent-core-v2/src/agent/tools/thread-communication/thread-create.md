Create a new independent top-level session thread only when the user explicitly asks. Unlike AgentRun, the new thread is user-owned, does not report its work back, and may start immediately if `prompt` is provided. For a local thread, `cwd` must be an existing absolute directory; `profile` names an enabled main-agent profile and `persona` names a stored persona. A persona may choose its profile and model when those fields are omitted. `from_subagent` names one of your own subagents (its agent id) and opens it as a thread instead of an empty one: the new thread continues that subagent's conversation, todo list and notes as its main agent, keeps the subagent's working directory and carries its model when the selected main-agent profile can use it, and leaves the original subagent and its result here untouched; it cannot be combined with `cwd` or `persona`. Initial permission mode cannot exceed the current mode.

To create a thread in another space, pass `bridge_id`, `connection_id`, and/or `workspace_id` to select the bridge and target workspace. The new session is top-level and starts at the target workspace's canonical root; cross-space creation rejects `cwd` and `from_subagent`. The target must resolve `profile` to an enabled main-agent profile. The bridge must grant `create` for the entire target workspace. Permission mode defaults to the caller's effective mode capped at `auto`; explicit requests above either limit are rejected. `idempotency_key` is optional and defaults to this tool call's ID; retrying the same request returns the same thread, while changing the request under that key is rejected. The result includes a `thread` reference that can be passed directly to `ThreadSend`, `ThreadRead`, or `ThreadWait` when the bridge grants those operations. For cross-space creation, `prompt_started: true` means the initial prompt was durably submitted; use `ThreadWait` to observe its progress or completion.

To interact later with a local thread, use ThreadList, ThreadSend, ThreadRead, and ThreadWait when enabled.
