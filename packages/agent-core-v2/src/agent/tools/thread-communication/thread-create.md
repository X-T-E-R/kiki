Create a new independent top-level session thread only when the user explicitly asks. Unlike AgentRun, the new thread is user-owned, does not report its work back by default, and may start immediately if `prompt` is provided. Pass `notify_on_terminal: true` (only valid with `prompt`) when you want a one-shot wake notification after the new thread settles (waiting for its active subagents and finite background tasks on completion), needs attention, or terminates (waking this thread if idle; bridged targets require `wait` permission). Leave `notify_on_terminal` unset if you do not need an automatic wake or if the new thread will communicate back via `ThreadSend`. For a local thread, `cwd` must be an existing absolute directory; `profile` names an enabled main-agent profile and `persona` names a stored persona. A persona may choose its profile and model when those fields are omitted. `from_subagent` names one of your own subagents (its agent id) and opens it as a thread instead of an empty one: the new thread continues that subagent's conversation, todo list and notes as its main agent, keeps the subagent's working directory and carries its model when the selected main-agent profile can use it, and leaves the original subagent and its result here untouched; it cannot be combined with `cwd` or `persona`. Initial permission mode cannot exceed the current mode.

To create a thread in another space, pass `bridge_id`, `connection_id`, and/or `workspace_id` to select the bridge and target workspace. The new session is top-level and starts at the target workspace's canonical root; cross-space creation rejects `cwd` and `from_subagent`. The target must resolve `profile` to an enabled main-agent profile. The bridge must grant `create` for the entire target workspace. Omit `permission_mode` unless you explicitly intend to override the target space's default: when omitted on a trusted `yolo` bridge while the caller is in `yolo`, the target space uses its own configured `default_permission_mode` (including `yolo`); otherwise `permission_mode` is capped by both the caller's effective mode and the bridge's permission ceiling (`auto` on untrusted bridges), and explicit requests above either limit are rejected (`permission_mode: "yolo"` succeeds only when both the caller is in `yolo` and the bridge grants a `yolo` ceiling). `idempotency_key` is optional and defaults to this tool call's ID; retrying the same request returns the same thread, while changing the request under that key is rejected. The result includes a `thread` reference that can be passed directly to `ThreadSend`, `ThreadRead`, or `ThreadWait` when the bridge grants those operations. For cross-space creation, `prompt_started: true` means the initial prompt was durably submitted; pass `notify_on_terminal: true` for automatic completion/attention wake or use `ThreadWait` to observe its progress.

To interact later with a local thread, use ThreadList, ThreadSend, ThreadRead, and ThreadWait when enabled.
