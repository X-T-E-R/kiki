Wait for an owned background task for a concrete same-turn dependency (e.g. verifying your own build or deletion); `timeout` is required. An interactive main agent outside active goal mode must not wait merely to collect automatically notifying subagent reports. A main-agent wait on a running subagent outside active goal mode requires `sync_wait=true`, a specific `task_id`, and a concrete `sync_reason`; routine report collection is not a valid reason. Do other useful work or end the turn with a brief pending status, then continue on notification; this neither cancels the work nor completes the user's task. Do not poll TaskWait/TaskOutput/TaskList/AgentList to hold that turn open. Subagents must instead resolve their own dependencies before returning a final receipt. With `task_id`, wait for that task; otherwise, for any task running at call time. A timeout leaves tasks running; reassess rather than automatically repeat. Terminal tasks reported here do not also send an automatic completion notification.
