Start a subagent with its own context for a bounded piece of work that benefits from running in parallel or from independent evidence. A lookup you can do in one or two calls is cheaper to do yourself. The child sees none of this conversation, so `prompt` must carry the goal, the paths and facts you already have, what it may change, and what result you want back. Give one owner a complete behaviour, including its callers, shared contracts and checks, instead of splitting coupled work by file; when several children depend on one interface, name the one that produces it so the others do not guess. Choose model, route and tools through the parameters, not in the prompt. Leave work you assigned to a child to that child, because a second writer on the same files produces conflicting changes.

`description` is a short label for the UI. Choose the role with `profile` or `route`, or supply `profile_file` for a new role definition; leave all three out when continuing an existing child with `resume`. The chosen role's tools, permissions and delegation limits apply to the child. Give a new child a `name` if you expect to address it again. Only you see the child's result: check the actual files or diff before relying on it, and send follow-up work to the same child. If a child times out, resume that child.

To continue an idle child, pass `resume` with its name or id. `context_mode` selects what it keeps: `direct` keeps its context, `compact` summarizes it with its current model first, and `fresh` rebuilds it from saved task state without calling the old model. The child's id, notes, todo list, history and workspace are kept in every mode. Leave out `model_alias` and `effort` to keep the saved ones. Changing the model on resume needs an explicit `context_mode` (or the legacy `allow_model_change=true`); `model_alias: "auto"` needs it only when it picks a different model. `compact` and `fresh` work only with the native executor.

Subagents may use AgentNotify only when the parent must change course before their final result; routine progress belongs in the final receipt.
