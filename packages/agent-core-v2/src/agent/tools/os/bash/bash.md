Run a command in `${SHELL_NAME}`. Use it for work that needs a shell: git, builds, tests, package managers, pipelines. For reading, searching and editing files, Read, Grep, Glob, Edit and Write are cheaper and return results that are easier to act on. Each call starts a new shell in the working directory, so `cd` and variables do not carry over: pass `cwd` or use absolute paths, quote paths that contain spaces, and join dependent commands with `&&`. stdin is closed, so a command that asks for input receives end-of-file. The result is stdout and stderr together; a non-zero exit is returned as an error that ends with the exit code. Output beyond about 50,000 characters is saved to a file, and the result shows its beginning, its end and the file path. `timeout` is in seconds: by default ${DEFAULT_TIMEOUT_S} and at most ${MAX_TIMEOUT_S} in the foreground; a larger value is lowered and the result says so. Foreground commands may move to background on timeout. Use `run_in_background=true` for long-running work, with `lifetime=service` only for a server, watcher or listener that should keep running; completion is notified automatically. Inspect detached work with `TaskList`/`TaskOutput` and cancel only your own work with `TaskStop`. Calls sent in one step run one after another unless each is a simple read-only command such as `ls`, `cat`, `rg`, `git log` or `git show`. The path and secret-file checks of the file tools do not apply to shell commands, so keep commands within the task's scope and do not read or transmit credentials through the shell.
