# 制作 Kiki 角色

把用户的人物设定做成能在新会话里使用的角色。角色决定「谁在说话」；执行配置决定「怎样完成任务」，两者可以组合。

## 1. 先选对产物

「温和但不盲从的写作伙伴，有头像，记住交流偏好」走这里。「只能读代码的审查子智能体」转 `kiki-profile`。只是切换已有角色时，用原生选择入口，不新建文件。

## 2. 把设定写成可交流的人物

从用户已有描述拟出身份、说话方式、遇到分歧时的行为、开场白和两三段代表性对话。用具体行为表达风格，例如先指出文章里最影响理解的问题，再给出一处改写，而不只是写「专业、友好」。只问会改变用途、记忆共享或执行配置绑定的缺口；没有要求就保留现有模型、权限与共享记忆设置。

## 3. 制作最小角色资产

制作前用 Read 阅读 `references/authoring.md` 的格式与保存参考；内置调用时，这份参考已附在下方。以角色设定文件和对话示例为起点，复用已有执行配置；确实需要新的执行角色时再调用 `kiki-profile`。

头像使用用户提供且有权使用的素材，通过角色页上传。没有素材就保留默认头像，不为完成角色创作要求用户开通图片服务。用户要求生成头像时，另行调用实际可用的生成能力。

## 4. 保存并检查

读本机安装文档，使用原生角色预览、保存或导入路径检查角色标识、字段、绑定和头像。已有角色先读取再修改，保留本次无关的内容。角色目录只交付设定和素材，不手工制造角色状态、目录索引或运行时记忆。

能自行完成的保存与检查直接完成；若当前没有可操作客户端，交付资产与一个必要的导入步骤，并明确尚未验证实际使用，别让用户重复抄写字段。

## 5. 在新会话里试用

检查角色列表、头像和开场白展示；新建会话，核对实际角色、执行配置与模型，用代表性对话检验风格，尤其是用户意见有问题时是否仍能温和指出。正在进行的会话保留自己的角色快照，改文件不会立即让原对话换人。

交付角色名称、资产位置与实际验证结果。导出分享卡片时明确是否包含记忆，默认不顺手带出交流记录。
