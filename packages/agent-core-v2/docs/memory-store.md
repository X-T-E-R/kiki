# Canonical Memory store

Use `IMemoryStore` for normal Memory consumers. `MemoryAuthorityStore` routes tools and the REST editor through the home’s persisted backend marker; a home without a marker keeps its legacy file authority. `ISqliteMemoryStore` remains the explicit isolated/internal SQLite boundary. Scope, review and off-policy checks stay with their existing consumers.

## Persistence and transactions

`IMemoryPersistence` lives in `src/persistence/interface/memoryPersistence.ts`; the local backend is `src/persistence/backends/sqliteMemory/`. The database is `<home>/store/memory-sqlite-v1/memory.sqlite`, outside the disposable cache. Its worker uses WAL and FULL synchronous commits. App disposal drains accepted operations and closes the worker.

`read(scopes, generation?)` returns a committed view. A generation freezes object membership and revisions across later writes; forget barriers always apply to older views too. Callers must resolve their permitted scopes on every call. The Store does this through `IMemoryScopes`; the persistence interface is an internal, already-authorized boundary.

`commit` atomically compares the expected generation and each object revision, then saves immutable revisions, current heads, evidence sources, independent human adjudications, pending entries, the journal and an operation receipt. A failed comparison leaves every target unchanged. A scope does not establish which conflicting fact is true.

Pass a stable `MemoryMutation.operationId` for retriable writes. The Memory tool uses session, turn and tool-call identity. After an unknown worker outcome, reopen and read `receipt(operationId, request)` before deciding whether to retry. Reusing an operation ID for different content fails. A worker failure does not trigger an automatic write replay.

Legacy revisions remain exact lookup tokens; new revisions start with `mem2:`. `getRevision(scope, id, revision)` reads a historical revision. Normal `get` returns the current object. User approval rechecks the proposal, target and any `covered_by` dependency in the same committed view. Delete creates a tombstone; undo creates new revisions and refuses to overwrite later edits.

## Read-only shadow import

`IMemoryShadowImport` in `src/app/memory/memoryShadowImport.ts` reads the permitted scope's `entries`, `inbox` and `journal.jsonl`. It writes only the independent SQLite store. `run(scope, after?)` imports at most 128 source files and 16 MiB per call; resume with `nextKey`. `complete` reports traversal completion, and `issues` reports invalid, changed or oversized sources. Keep those sources and resolve the findings before cutover.

The importer preserves raw payloads, legacy IDs, revisions, operation IDs, proposal targets and deleted preimages. Repeating it retains unchanged payloads. Native corrections are not overwritten by a later legacy payload. An absent source file is not yet a deletion instruction: inventory reconciliation and the authority switch belong to the migration transaction.

## Backend authority and read-only recovery

`IMemoryAuthorityService` owns explicit migration and recovery. Its state is stored atomically at `store/memory-authority-v1/backend.json`, with a backend, mode and monotonic epoch. The router rereads that state for operations; `prepare()` refreshes optional snapshot availability before safe-step projection. Legacy homes keep their existing projection, while SQLite homes use fixed-generation working sets. Missing or truncated SQLite authority fails closed instead of opening an empty replacement or reading stale legacy content.

Before calling `migrate({ operationId, olderWritersStopped: true, maxPages? })`, upgrade or stop every other process that can write the same home. Updated `MemoryStore` legacy writers share the home-wide authority lease and reject writes after cutover. Binaries predating this protocol cannot understand its marker and must be stopped; the marker does not prevent them from writing the accessible legacy directory. `olderWritersStopped` records operator confirmation, not a process-inventory check. Shadow import does not change authority or dual-write the source files.

Migration persists `mode: migrating` before importing its final source pages. Each call processes at most `maxPages` pages, default 8; each page retains the shadow importer’s file and byte bounds. Resume with the same operation ID after a budget pause or restart. All normal edits stay blocked until migration completes or `cancelMigration(operationId)` explicitly restores legacy editing. Invalid files, broken journal links, unmatched native heads and conflicting source lineages remain in `migration.issues`; cancel, repair the reported sources and restart with a new operation ID. Final reconciliation applies recoverable legacy deletions only when their exact journal preimage matches, checks current object identities and preserves proposal targets, then publishes SQLite authority. Subsequent tool and editor writes leave the original files unchanged.

`recoverReadOnly()` holds the same write lease while creating a complete SQLite backup, a legacy-shaped current-view export and a manifest under `store/memory-recovery-v1/<recoveryId>`. The database backup retains post-cutover operations, immutable revisions, sources, human adjudications, proposals and forget barriers. The Markdown view contains current objects and pending entries; the database is the recovery authority for data the old format cannot express. A package-publication failure leaves the live SQLite authority editable.

After package publication the state is `backend: sqlite, mode: readonly`: reads use the governed current view and every normal mutation is rejected. This is a read-only recovery mode. To resume normal editing, call `resumeEditing(recoveryId, expectedEpoch)` with the current status; a changed ID or epoch is rejected. Do not restore the original legacy directory over post-cutover corrections or forget barriers. Restoring a backup requires its full governed database and the latest applicable adjudications and barriers before reads reopen.

The authenticated management API is documented in [Server API](../../../docs/en/server/rest-api.md#memory). Its forget flow keeps preview revisions explicit, and historical revision reads are marked as historical rather than current guidance.

## Source ingestion and irreversible forget

`ingest({ mutation, unit })` is the host ingestion boundary. The host supplies the stable source-unit ID, original payload, locator and provenance classification; model-generated text must not assign its own trust. Only owner/agent sources are eligible. Session-derived sources require `sessionKind: 'interactive'`; untrusted, system and background sources are rejected before storage. A unit identifies one independently correctable fact, not an entire session. A changed original payload requires a new source revision identity.

Re-extracting an admitted unit resolves its current corrected, pending or archived object rather than creating another object. Supersede transfers predecessor source lineage atomically; delete blocks re-extraction until undo restores the object. `provenance(scope, id)` returns the original sources, independent adjudications and related object IDs.

Shadow imports register a stable fact identity from scope, writer/session/turn, sorted basis references and exact body, excluding the memory ID and title. Re-importing that fact under another ID reports `source_lineage_preserved` instead of restoring its old claim. Missing source coordinates leave an explicit source identity unavailable; the importer still enforces object-ID barriers. Lorebook imports use their writer coordinates, title and complete content as the source unit; a repeated admitted item does not create a new object, and a forgotten item is skipped.

Call `previewForget(scope, ids)` before confirmation. It expands the complete source lineage and returns exact IDs, revisions and current entries, including recoverably deleted tombstones (`entry: null`). Show the complete set to the user. `forget(scope, targets, operationId)` rejects changed revisions or an incomplete lineage, then atomically publishes persistent object/source barriers and removes Memory content, historical views and replay receipt bodies. The same exact source cannot return under a new memory ID, while a distinct fact from the same session remains eligible. This action cannot be undone.

The barriers do not remove History, external files or independently held backups; their owners must perform those operations. A backup-restore entry point must install current barriers before exposing restored content. SQLite schema 2 adds source links and barriers and backfills stable identities for schema-1 imported objects whose original revisions remain available.

The source lifecycle adapts OpenClaw's trusted-candidate, provenance reservation, predecessor-lineage and forget units. Source revision, modifications and the MIT license are recorded in `src/app/memory/NOTICE` and `OPENCLAW-LICENSE`.

## Recall and request working sets

`ISqliteMemoryStore.snapshot(scopes)` reads all permitted objects at one committed generation. `checkpoint()` reads only persistent generation metadata, without loading object bodies. The safe-step consumer reuses its working set until the request, generation, persona or a validity deadline changes. The file Store keeps its existing projection behavior.

`memoryRecall.ts` adapts OpenClaw's lexical/vector union, weighted component scores, exact-identity tier, MMR diversity and keyword-only fallback. Kiki supplies scoped object IDs and authoritative revisions; stale semantic candidates are discarded. Local BM25 uses the existing ASCII/CJK tokenizer over the bounded current object set instead of adding OpenClaw's file-path FTS schema. Its title contribution is a bounded weight, not an exact-title million-point bonus. Scope and update time do not decide truth. No Memory semantic provider is configured or called by this unit; the pure ranking input accepts already-authorized semantic candidates without creating an upload path.

MemorySearch and MemoryRead share `memoryContext.ts`'s complete result builder. Search attempts whole units within 24,000 UTF-16 units and 6,000 estimated tokens, including framing and metadata. A result that does not fit remains an explicit `complete: false` reference with an exact read target. If reference metadata alone exceeds the budget, the tool returns a smaller-`page_size` recovery rather than an oversized page. List remains a reference inventory.

The agent working set uses the same complete content, attribution and whole-body ranking as Search, with the configured character budget and an additional 1,000-estimated-token ceiling. Relevant units precede unrelated pinned entries; expired and pending entries do not enter the automatic working set. Title matches contribute through the shared ranker rather than overriding its order in a second selection pass.

`AgentMemorySnapshot.refreshIfDirty(request?)` obtains the latest actual user/child-assignment text from context when no request is supplied, including the `runAgentTurn` subagent origin and parent messages. Current task goals, directives, next actions and explicit `[m_id]` references supplement continuation requests. It ignores injected, tool and compaction-summary text. Configuration changes remove disabled worksets at the next safe step. Native safe steps publish through the existing profile runtime snapshot. Binding the SQLite Store adopts that dynamic layout once; later working-set updates leave the stable system prefix unchanged.

`memoryProjection.ts` reuses complete current explicit units by scope, ID and revision. Duplicate tool results become `memory_content_reused` references, and matching units are removed from the outgoing host workset without refilling it with lower-ranked content. Reference-only results do not suppress a complete automatic unit. A currently valid successful write omits only its duplicate `body` argument and preserves every other original parameter, including explicit nulls and audit metadata. Failed writes remain unchanged.

The projector removes superseded host-owned memory sections and validates structured MemoryRead, MemorySearch and MemoryWrite results against the current scope and revision view. Changed entries become `memory_revision_changed` references; forgotten or inaccessible entries become `memory_unavailable`. Invalidated write arguments keep only minimal addressing references, removing free-text metadata as well as the body. Tool call/result identities and canonical history remain intact; ordinary user text and other tools are not rewritten. A disabled or unavailable governed view removes explicit Memory payloads without querying another scope. Relay, model-summary compaction and fresh model-switch packages carry structured scope, ID and `observed_revision` references instead of embedding derived bodies. These historical observations require a current scoped read and remain usable when automatic selection omitted the entry. Restored and forked histories use the same outbound projection.

External execution passes the outbound request text explicitly and carries the same read-only working-set payload only when its binding selects `kiki_context: ["memory"]` or `executor_prompt.include: ["memory_snapshot"]`. Explicit off choices remain effective. The actual ACP request boundary is `AgentExecutionService.run` immediately before `session.run`; native captures use `TestAgentContext.llmCalls` after the safe-step injector.

## Integration boundary

The runtime router, explicit migration and read-only recovery API are implemented without automatically migrating existing homes. SDK and npm builds emit `memory-worker.mjs`; SEA registers, extracts and configures the same worker through the native asset manifest. The native smoke checks a real commit, complete read, receipt, database backup and clean worker exit. Revision-bound Markdown import preview, the GUI governance consumer and the pre-protocol writer boundary above remain required before production migration. The MemorySearch complete-response contract applies to both Stores.

`test/app/memory/sqliteMemory.test.ts` covers transactions, source lifecycle, recall fusion, complete-response budgets, cross-Store refresh, the four namespace forms, resumable migration, separate legacy-writer rejection and independent reopening of a recovery database. `packages/kap-server/test/memory.test.ts` exercises the authenticated HTTP editor, migration, forget preview, historical revision removal and read-only recovery/resume. `test/agent/tools/memory/memoryConsumption.test.ts` captures actual native main/child requests, correction/forget replacements and relay recovery. `test/agent/executor/externalExecutor.test.ts` captures explicitly admitted and opted-out ACP request payloads.
