# kap-server Agent Guide

The Kiki server, backed by the DI × Scope agent engine (`@kiki/agent-core-v2`, App/Session/Agent scopes with separate WorkspaceInstance/Program runtime ownership). Exposes sessions over REST + WebSocket (`/api` + `/api/ws`); bootstrapped from `src/start.ts` and consumed by `apps/kimi-code`.

## Comment conventions

No comments — no file headers, no section banners, no statement-level narration; the code is the source of truth. The only exception is JSDoc attached to exported symbols (it flows into the generated `.d.ts` and IDE hover). Lint-suppression directives (`oxlint-disable` / `eslint-disable`) are allowed where they suppress an active rule for a deliberate pattern; other tooling directives (`@ts-expect-error`, `@ts-ignore`, …) stay banned — fix the underlying type problem instead. Enforced by `scripts/check-no-comments.mjs` (part of `pnpm lint`).

## Routes

- Prompt and edit/regenerate authentication uses `lib/promptAuth.ts` to check the requested model, a newly selected profile's model, or the current agent's bound model. The global default is only a fallback for an unbound agent or an unpinned new profile; an unrelated default provider must not block a bound session. Keep this preflight non-mutating so rejected or queued requests do not change the active model.

- Session create/resume/fork routes use the App-scope `ISessionManager` facade. Session and registered-workspace fs routes materialize through `IWorkspaceInstanceManager` and bind the requested runtime capabilities. Draft absolute-root search/suggest use a request-local `LocalRuntime` without workspace registration or a Program; cwd profile/capability previews use the existing catalog loaders in a disposable no-watch snapshot. `fs:search` also accepts a workspace reference (registered id or absolute root) in the `{session_id}` slot; the first-class session-less forms are `POST /api/workspace/fs:search` and `/api/workspace/fs:suggest` (the workspace reference travels in the body). Final session creation and explicit workspace registration retain `createOrTouch`.
- Read-only routes on the session-open path (`GET /api/agents/capabilities`, `GET /api/sessions/{id}/skills`) must answer cold sessions from `ISessionIndex` plus persisted stores instead of resuming them; `resumeSessionById` is reserved for actions that need the live session (prompts, approvals, questions, fs, terminals). Agent-panel persisted metrics are cached per agent with a 30s TTL for live agents and a 600s TTL for dead agents, and the scan never covers live agents whose replayed accounting is complete.
- Session media downloads and previews accept canonical/staged file IDs and `blobref:<agentId>:<sha256>` IDs for saved tool-result bytes. Indexed sessions resolve their workspace through `ISessionIndex` and read canonical media through `ScopedMediaStore` without acquiring or restoring the session; canonical bytes and metadata take precedence over the global staged-upload fallback. Unindexed live sessions retain the operation lease. The blobref branch validates the agent and hash and reads `agents/<agentId>/blobs` without restoring a cold session; it must not substitute the current host file for a missing historical result. Blobref responses use a generic binary MIME; the transcript's validated blobref carries the image/video MIME for preview. Allowed browser origins can read the existing `ETag`, `Content-Disposition` and `Content-Range` response headers for preview revalidation, original names and range receipts; origin admission and authentication stay unchanged.
- The RPC surface is `/api/debug/*` — a reflection dispatcher over the ENTIRE scoped DI registry (every Service callable, no whitelist, Workspace scope addressable alongside App/Session/Agent; `src/transport/registerDebugRoutes.ts` + `serviceDispatcherRoutes.ts`), mounted only with `--debug-endpoints` on a loopback bind and gated by the global bearer auth; repo dev scripts pass the flag. Lookup falls back to the Feature contributed-service table (`features/featureRegistry`), so Feature-contributed Services (`contributeService`, which bypasses the static scoped registry) stay callable even though `GET /channels` does not list them; kernel tokens registered neither way (e.g. `instantiationService`) stay unreachable.

## Usage aggregation cache

Usage aggregation compares agent inventories, wire size, mtime and offset when reusing cached or checkpointed results. An external rewrite that preserves both file size and mtime is not detected; its previously cached usage may remain marked complete until another fingerprint input changes.

## Advanced session and MCP surfaces

`GET /api/sessions/query` (`src/routes/v2/sessions.ts`, registered by the unified route entry) provides the advanced session query. It shares the flat session routes' wire conventions: every response is wrapped in the `{ code, msg, data, request_id }` envelope with the business outcome in `code` (`40001` invalid query params with `details`, `40922` page_token mismatch), and the HTTP status only reports server-/transport-level outcomes (401 from the global auth hook, `50001` via the catch-all error hook). Pagination is an opaque `page_token` (base64url JSON: version + sha256 query-condition fingerprint + keyset position) — any condition flip mid-pagination fails 40922. Response domains are grouped (`workspace` / `meta` / `activity` always; `git` opt-in via `include=git`, deduped per unique cwd with a 60s TTL cache over `IGitService`, all git/gh failures degrading to cached null fields). Sorts/filters are applied at the edge over the index's canonical `updatedAt desc, id desc` drain, so all three sort orders share one comparator + cursor encoding; `activity.status` maps the core `ISessionActivityView` facts (pending interaction > active turn > failed last turn > idle; cold sessions are always `idle`).

`/api/mcp/*` (`src/routes/v2/mcp.ts`) exposes the agent-core-v2 `mcpManagement` plane: CRUD on the user-level `mcp.json` (`GET/POST/PUT/DELETE /mcp/servers[/{name}]`; `PUT` takes a name-less config body, the path owns the identity), a connection-test probe and the locator-addressed inspection catalog (`POST /mcp/servers:test` / `:inspect`, declared with the doubled-colon static-segment convention), the auth-status surface (`GET /mcp/auth-statuses?verify=`), and the locator-addressed OAuth flow operations (`POST /mcp/auth:begin|complete|cancel|reset`). Engine `Error2`s map `mcp.server_not_found` → `40408`, `request.invalid` / `config.invalid` → `40001`, and `mcp.oauth_failed` → `40929`. `auth:complete` is a long poll (up to the flow's `timeoutMs`): the server disables Node's default `requestTimeout` (`start.ts`), and the handler aborts the engine wait when the client connection closes early. The klient facade mirrors the same surface as `global.mcp.*` with identical wire codes, plus the name-only `global.mcp.resolveByName` helper (REST clients compose locators from the `GET /mcp/servers` catalog).

## Transcript surface

Implements the op-batch sequencing contract:

- `TranscriptService.dispatchOps` assigns every dispatched batch a per-agent consecutive `seq` and retains it in a bounded in-memory journal (`TRANSCRIPT_OPS_JOURNAL_CAPACITY`, dies with the live store). WS `transcript.ops`/`transcript.reset` payloads carry the seq/watermark.
- A numeric `transcript_since` subscription cursor (carried, with the per-agent grades, by the `subscribe_v2` control frame — the only transcript subscription channel; its agent-grained counterpart `unsubscribe_v2` detaches listed agents' streams, or the whole session's when `agent_ids` is absent, letting the detached agents' legacy events flow again) replays journaled batches instead of a baseline reset when the journal covers it, and `GET /sessions/{id}/transcript/ops?since_seq=` serves point-to-point catch-up (`complete: false` = journal can't cover or session cold → caller falls back to a full refresh).
- Beside the paged route, `GET /sessions/{id}/transcript/plan?agent_id=[&tool_call_id=]` projects an agent's ExitPlanMode plan info (content / path / options / review outcome; `tool_call_id` narrows to one call, omitted lists every recoverable plan) from the first available fact — the linked approval interaction's persisted request display, the live tool frame's display, or the tool result output text.
- The baseline `transcript.reset` is a bounded snapshot (`TRANSCRIPT_RESET_TAIL_TURNS = 20`): the newest 20 turns plus global tasks/interactions/prompts/meta and `has_more_older`. `turn` grade redacts step/frame detail (roster/task/meta only); `delta` grade carries the visible timeline.
- When a WS connection subscribes to the transcript protocol (grade ≠ `off` for an agent), the broadcaster suppresses the transcript-projected `session_event` types for that connection × agent (`TRANSCRIPT_PROJECTED_EVENT_TYPES` + `suppressedByTranscript` in `sessionEventBroadcaster.ts`; cursor replay via `getBufferedSince` applies the same filter). The set includes the prompt queue variants already projected as `prompt.upsert` (`prompt.queued`, `prompt.replaced`, plus submitted/completed/aborted/steered). Suppression is only a per-connection send view — the journal still records everything, and connections without transcript grades are unaffected.

## History navigation search

`services/history/historySortedSearch.ts` prepares the shared SQLite navigation projection through a fixed wire watermark before querying visible text spans. Preparation and text reads share an 8 MiB / 50,000-record per-call scan budget; bounded head/tail source-proof reads are separate validation IO. `newest`/`oldest` use `(coalesce(time,0), key)` keysets across pages. `relevance` scores only the current newest-first scan page with the shared lexical matcher and reports `page_local_relevance` while unscanned candidates remain. V2 cursors bind request, source stat fingerprint, incarnation and projection generation; source appends or mutations invalidate them. V1 scan cursors retain source-order continuation with an explicit warning. Search-order indexes are additive and removable; SQLite table schema stays at version 2, and all navigation rows remain rebuildable from canonical wire files.

## Session events

- The session's work aggregate behind `event.session.work_changed` (`busy` / `main_turn_active` / `pending_interaction` / `last_turn_reason`) is owned by the core's `ISessionActivityView` (`sessionActivity` domain, Session scope): the broadcaster only schedules the wire emission around turn frames (`busy:false` lands after `turn.ended`), and `resolveSessionFacts` (`src/routes/sessions.ts`) reads the same view — never fold per-agent activity at the edge.
- Delivery split on `/api/ws`: global events (`session.meta.updated` and the `event.session.*` / `event.workspace.*` / `event.config.*` families, including every activated session's `event.session.work_changed`) fan out to EVERY established connection — `WsConnectionV1` registers itself via `broadcaster.addGlobalTarget` on construction and unregisters on close — while session/agent-grained events only reach connections subscribed to that session (subject to `agent_filter` and the transcript suppression above); transcript frames are a separate channel governed by the per-agent grades alone and bypass `agent_filter` entirely.

## Global search

The global search surface is `POST /api/search` (`src/search/` + `src/routes/search.ts`), backed by SQLite at `<home>/search-index-v2/index.sqlite` by default in CLI/TUI. Set `search_backend = 'minidb'` or `KIKI_SEARCH_BACKEND=minidb` to select the retained MiniDb index at `<home>/search-index`. Desktop SQLite stays off by default; `[search] enabled=true` or the `desktop_search` setting enables it after restart, subject to the indexer's FTS/trigram and free-space selfcheck. `[search] index_subagents=true` enables truncated subagent user, assistant and tool indexing; the default indexes only main-session content and titles. `SqliteSearchHost` keeps SQLite queries in a 256 MiB old-space worker thread (16 MiB page cache; eight active queries with a bounded waiting queue) and writes in a child process that requests 256 MiB (dev) or 384 MiB (SEA) old-space, reports RSS, self-exits on its memory budget, and reconnects with backoff. The `local` SEA profile keeps its 8192 MiB startup flag for the desktop backend, but enables SEA `execArgvExtension: 'cli'` so the indexer child can pass `--node-options=--max-old-space-size=384`. The release SEA continues to honor the indexer's `NODE_OPTIONS` limit. Writer election uses `BEGIN IMMEDIATE` on an adjacent SQLite lease database; concurrent hosts query read-only. The native SEA entry dispatches `__search-indexer` before ordinary bootstrap and embeds the query worker as a runtime asset.

- SQLite sync is queued in the indexer process. Each committed session updates `indexedSessions`/`totalSessions` through `SqliteSearchHost.snapshot()` while search keeps returning partial results in `building`. The default unfiltered `score` query uses FTS5 rank with a 64-document candidate cap and reports `incomplete: 'candidate_cap'` on overflow. The read-only query worker coalesces identical requests for at most 500 ms, invalidated immediately by SQLite `data_version` on a writer commit. `status().indexer` exposes RSS, WAL and progress. SQLite `reindex()` clears owned derived rows and incrementally resyncs the current session inventory in the elected writer; a read-only host rejects it. `POST /api/search/retry` clears indexer backoff and restarts a stopped writer.
- On the MiniDb rollback path, everything that touches its index lives in the host-agnostic core (`src/search/indexCore.ts`): open/reopen (writer election, corruption rebuild), read-only freshness (fingerprint + WAL catch-up), the incremental sync pass, the bounded index-route query execution, reindex, and close. It runs in one of two hosts behind the `SearchBackend` seam: a dedicated **worker thread** (`src/search/worker/` — `host.ts` RPC client + `entry.ts` worker entry + `protocol.ts` contract; the default) or the **inline** in-process host (the rollback). The `search_worker` experimental flag (`KIKI_EXPERIMENTAL_SEARCH_WORKER`, default ON) selects the host at service construction. The main thread keeps only query normalization, page-token encode/decode, the sync coordinator, the live route, and hit projection; worker failure/crash surfaces as recognizable `building`/`degraded` pages — never an implicit inline fallback. Host lifecycle guards: the worker reports the write-lock token via a `lockToken` event the moment the lock is acquired (`OpenOptions.onLockAcquired`), so a mid-open crash leaves a reapable lock; an orphan detector reaps a same-pid lock line whose token belongs to no live worker of the process and restarts (never a silent permanent read-only); every RPC carries a watchdog timeout (a wedged worker is terminated and restarted with backoff); `beginClose` reaches the worker-side core via a control message so dispose never wedges behind a running sync; and the token-pinning generation is salted per worker boot, so page tokens never validate across a worker restart.
- It serves two modes: `terms` (the default — minidb's inverted text index over ASCII words + CJK uni/bigrams, no positions, term-level AND) and `literal` (substring-exact search: a hashed 2/3-gram index supplies candidates, every candidate's text is then confirmed with `includes`, so hits carry zero false positives; literal ignores `sort` and returns newest-first).
- The index route is fully bounded (stage 4): a search request serves the currently published generation and never awaits a sync/reopen/reindex — it kicks the single-flight + debounced background coordinator instead, and reports `index_state.stale` / `index_state.degraded` when serving a behind view or after a failed refresh, and `index_state.state: 'building'` while the served handle's text base is still being (re)built by the deferred fallback build (searches get the empty building page, never a partial result).
- The sync coordinator keeps a warm session-summary/mtime inventory and watches `<home>/sessions` for targeted metadata and wire invalidation. On an unchanged pass it sends cached source mtimes to the worker, which persists them in per-session `SessionMetaDoc` rows instead of statting every source again. A 10-minute full source-stat pass repairs missed watch events, a 30-minute paged inventory refresh catches same-count additions/removals, and a count mismatch immediately forces that refresh; if the watcher cannot start, the periodic source-stat pass remains active rather than falling back to per-request scans. Direct `SearchIndexCore.sync()` callers without cached mtimes retain the original stat path.
- The aggregate lifecycle (stage 5) — `stopped → opening → ready → building/degraded → closing` — is diagnosable two ways: `IGlobalSearchService.status()` keeps its historical semantics (may kick/await the open + read-only refresh) but never throws — a failed open/worker answers `lifecycle.state: 'degraded'` with the error as detail — and `lifecycleReport()` is the synchronous local read that never kicks an open or spawns the worker, so it still answers during a minutes-long first open or a worker backoff (both surface on `/api/debug/globalSearch/*`). A corruption-triggered rebuild is its own logged outcome (`search-index corruption detected; rebuilding from scratch`), distinct from building/degraded lines.
- Every query runs under explicit budgets (max terms, postings visits via `MiniDb.searchBoundedAsync`, candidate caps, confirmation text volume, a match deadline) with over-budget pages flagged `incomplete: 'candidate_cap' | 'postings_budget' | 'deadline'`. The budget VALUES are centralized: per-query work budgets in `src/search/searchService.ts` (mirrored as service test knobs), worker-host budgets in `src/search/worker/host.ts` (ready/close/request/sync watchdogs, heap cap, crash backoff), minidb's process-wide worker slots and slice budgets in `packages/minidb/src/maintenance.ts` / `recovery.ts`. Query concurrency is structural, not a semaphore: one worker thread per service serializes all index-route CPU work, each query is individually budgeted and watchdogged, and the worker heap cap turns a pathological burst into a degraded-restart rather than a main-process stall.
- Pagination is keyset over `(time, key)` / `(score, time, key)` with versioned v2 tokens pinning the index generation (a rebuild/reopen/rescan invalidates old tokens with `invalid_page_token`; legacy v1 offset tokens are still accepted and upgraded), and per-session sync scans only that session's file-meta keys (`\0meta\file\<sessionId>\<hash>`, migrated from the pre-v2 hash-only keys by a one-time background pass).
- Unless `indexOnly` is requested (HistorySearch uses it to recover old resident-evicted turns), when `container.session_id` is provided and that session is live in this process (`TranscriptService.forSessionLive` returns a store, wired via `setLiveTranscriptSource` in `start.ts`), BOTH modes instead scan the in-memory transcript store (turn prompts + assistant text/tool-result frames, history established via `whenReady`/`ensureAgentHistory`) — no index involved; terms-mode live hits are scored Σ log(1+tf) (comparable only within a route, per the `GlobalSearchSource` contract), live-route errors never fall back to the index, and the response's `source: 'live' | 'index'` field (also mixed into the page-token fingerprint, so a mid-pagination route flip invalidates the old token) tells the caller which route served the page.
- Dev/test worker runtime: the worker entry (`src/search/worker/entry.ts`) loads from TS source under Node's native type stripping plus a repo-local `.js`→`.ts` resolve hook (`src/search/worker/register-dev-hooks.mjs`); the npm bundle emits `dist/search-worker.mjs` (`apps/kimi-code/tsdown.dist-worker.config.ts`); the SEA binary embeds it as the `kap-search-worker` runtime asset (`apps/kimi-code/scripts/native/manifest.mjs`), installed at startup by `apps/kimi-code/src/native/search-worker.ts`.
