# kap-server Agent Guide

The Kiki server, backed by the DI × Scope agent engine (`@kiki/agent-core-v2`, App/Session/Agent scopes with separate WorkspaceInstance/Program runtime ownership). Exposes sessions over REST + WebSocket (`/api` + `/api/ws`); bootstrapped from `src/start.ts` and consumed by `apps/kimi-code`.

## Comment conventions

No comments — no file headers, no section banners, no statement-level narration; the code is the source of truth. The only exception is JSDoc attached to exported symbols (it flows into the generated `.d.ts` and IDE hover). Lint-suppression directives (`oxlint-disable` / `eslint-disable`) are allowed where they suppress an active rule for a deliberate pattern; other tooling directives (`@ts-expect-error`, `@ts-ignore`, …) stay banned — fix the underlying type problem instead. Enforced by `scripts/check-no-comments.mjs` (part of `pnpm lint`).

## Routes

- Prompt and edit/regenerate authentication uses `lib/promptAuth.ts` to check the requested model, a newly selected profile's model, or the current agent's bound model. An unbound first-message agent checks the effective default profile before falling back to the global model; the core binds that profile at prompt launch, not session creation or auth preflight. The global default is only a fallback for an unbound agent or an unpinned new profile; an unrelated default provider must not block a bound session. Keep this preflight non-mutating so rejected or queued requests do not change the active model.

- Session create/resume/fork routes use the App-scope `ISessionManager` facade. Session and registered-workspace fs routes materialize through `IWorkspaceInstanceManager` and bind the requested runtime capabilities. Draft absolute-root search/suggest use a request-local `LocalRuntime` without workspace registration or a Program; cwd profile/capability previews use the existing catalog loaders in a disposable no-watch snapshot. `fs:search` also accepts a workspace reference (registered id or absolute root) in the `{session_id}` slot; the first-class session-less forms are `POST /api/workspace/fs:search` and `/api/workspace/fs:suggest` (the workspace reference travels in the body). Final session creation and explicit workspace registration retain `createOrTouch`.
- Read-only routes on the session-open path (`GET /api/agents/capabilities`, `GET /api/sessions/{id}/skills`, `GET /api/sessions/{id}/agents/{agentId}/hooks`) must answer cold sessions from `ISessionIndex` plus persisted stores instead of resuming them; `resumeSessionById` is reserved for actions that need the live session (prompts, approvals, questions, fs, terminals). Cold hook inspection leases the workspace snapshot and folds persisted binding and hook-clock records without acquiring a session operation or restoring its dispatcher. It preserves global rules and reports invalid workspace configuration rather than returning an empty rule list. Existing live agents use their active hook inspection. Cold session-list persona labels use the indexed summary or legacy metadata, not a separate full-wire scan for each row. Agent-panel persisted metrics are cached per agent with a 30s TTL for live agents and a 600s TTL for dead agents, and the scan never covers live agents whose replayed accounting is complete.
- Session media downloads and previews accept canonical/staged file IDs and `blobref:<agentId>:<sha256>` IDs for saved tool-result bytes. Indexed sessions resolve their workspace through `ISessionIndex` and read canonical media through `ScopedMediaStore` without acquiring or restoring the session; canonical bytes and metadata take precedence over the global staged-upload fallback. Unindexed live sessions retain the operation lease. The blobref branch validates the agent and hash and reads `agents/<agentId>/blobs` without restoring a cold session; it must not substitute the current host file for a missing historical result. Blobref responses use a generic binary MIME; the transcript's validated blobref carries the image/video MIME for preview. Allowed browser origins can read the existing `ETag`, `Content-Disposition` and `Content-Range` response headers for preview revalidation, original names and range receipts; origin admission and authentication stay unchanged.
- Host-file and session media previews stop responding when the client disconnects; their source iterators and session operation leases still close. Set the media MIME only after a preview succeeds, and send failure envelopes as JSON. The catch-all error handler replaces binary framing and the route's success serializer before sending an error; keep the async `onSend` path covered by `workspaceFs.integration.ts`, `inlineMedia.test.ts`, and `transport-errors.test.ts`.
- Office document previews render temporary copies through the installed, enabled `kiki-office` prerequisite with `IHostProcessService` owned-tree execution (`services/documentPreview/officeCliPreview.ts`). Abort and timeout terminate the owned tree even after root exit; unconfirmed cleanup preserves scratch rather than deleting files still in use. Successful process exit commits normal release before late cancellation. Host audio/video elements mint a revocable 30-minute capability through authenticated loopback `POST /api/fs:media-preview`; `GET /media-preview/:id` streams bytes with Range without bearer headers, and `DELETE /api/fs:media-preview/:previewId` revokes it. These host-path capabilities do not resolve historical session file IDs. Canonical session audio and video mint through the same `registerHostMediaPreviewRoutes` owner: authenticated loopback `POST /api/sessions/:sessionId/media-playback` with `{ file_id }`, then `GET /media-preview/:id` and `DELETE /api/sessions/media-playback/:previewId`. That route owns the shared 64-grant, 30-minute table. A host path does not satisfy a session file id, and a missing canonical file is not read from the host. A live session lease is released once when playback finishes, the client disconnects, or the stream fails; a rejected release is logged as `session media cleanup failed` and is not left unhandled. Mint and open pass the request-close signal into `openSessionMedia`. Cold `blobref:<agentId>:<sha256>` reads use `ISessionIndex` and `IBlobStore` and do not resume the session. The download response for those blobs stays `tool-result.bin` and `application/octet-stream`; playback projects `audio/*` or `video/*` only from at most the first 512 bytes, not from a host path or that generic name. Keep renderer lifecycle, page/sheet projection, and stream/revocation covered by the corresponding documentPreview, hostMediaPreview, and sessionMediaPlayback tests.
- The RPC surface is `/api/debug/*` — a reflection dispatcher over the ENTIRE scoped DI registry (every Service callable, no whitelist, Workspace scope addressable alongside App/Session/Agent; `src/transport/registerDebugRoutes.ts` + `serviceDispatcherRoutes.ts`), mounted only with `--debug-endpoints` on a loopback bind and gated by the global bearer auth; repo dev scripts pass the flag. Lookup falls back to the Feature contributed-service table (`features/featureRegistry`), so Feature-contributed Services (`contributeService`, which bypasses the static scoped registry) stay callable even though `GET /channels` does not list them; kernel tokens registered neither way (e.g. `instantiationService`) stay unreachable.

## Durable prompt admission

`routes/prompts.ts` accepts explicit `admission: "durable"` on the existing submit route; ordinary submissions keep synchronous launch/block semantics. `services/promptIngress.ts` locates the saved session through an `ISessionIndex` point read, checks the named child against saved metadata, and persists the original request plus canonical media through the App stores before acknowledging. The ingress metadata and 64-key pages contain previews; full payloads and resolved receipts are separate atomic documents. GET list/point reads never resume a session. API fields, pagination and recovery actions are documented in [`docs/en/server/rest-api.md`](../../docs/en/server/rest-api.md#prompts).

The background consumer uses the original prompt ID and fingerprint through the normal validation/reservation path. Before an uncertain retry, it must read the core receipt successfully; a timeout is not absence. Requests from a stopped owner become held rather than automatically replaying external work. A per-request worker lock prevents a second server from taking an active request. Cancellation during restore releases the operation pin immediately; after submission may have begun, it remains held until core cancellation is reconciled. Compact receipts retain original content-slot mappings, including file parts expanded into text. `test/prompts.integration.ts` covers stalled cold restoration, durable reads/cancellation, restart holds, strict receipt recovery and expired-upload retries through the real HTTP client.

Restore admission reports optional `restore_progress` (`phase`, `started_at`, `elapsed_ms`, one-based `queue_position`) on the existing saved-request reads. Core restore attempts expire at 60 seconds; ingress preparation expires at 120 seconds until `beforeSubmit` commits the submitting stage. Terminal receipts freeze progress. Identical requests with a new ID while the original is restoring become `held` with `admission_duplicate_of`; only explicit resume submits that copy. `test/prompts.delivery.integration.ts` covers the deadline, leaf phase, duplicate hold and stable receipt recovery.

## IM session bridge

`services/imSession/bridge.ts` shares a listener only among instances with the same provider kind and credential hash. Restarting a listening member with changed credentials starts a separate connection; members still listening on the old credentials keep their connection until its last member stops. When the canonical member changes credentials, reanchor the old group's bindings, tickets, outbox, deduplication keys and cursor to a remaining member. Keep account identity checks on inbound routing and reject events from retired listeners.

Group `topic` scope requires a nonzero `topic_id`; a stored no-topic `topic` binding remains sender-only. Scope/ownership checks are per provider instance and account. Confirm and PATCH must preserve binding, discovery, input owners and open replies after a failed save; keep validation and identity conflicts in the existing HTTP 200 business envelope. Sender bindings without `group_policy` still wake on every message, while new topic/chat bindings default to `mention_or_reply`. A session target does not require a persona.

Interaction delivery isolates failures per binding and attempts later bindings before reporting an ordinary send failure. The persisted internal `BindingRecord.interactionFailure` records only `feishu_thread_context_missing` or `wechat_group_unsupported`. These targets retain pending outbox entries and ticket IDs without repeated send attempts; `im interaction delivery blocked` logs the binding ID, instance ID and diagnostic code. A new inbound message for the same Feishu identity clears the missing-context block, allowing still-pending entries to use the new thread reply context. WeChat groups remain unsupported and never fall back to a private chat. This internal block is not a `connection_detail` field. Regression coverage lives in `bridge.test.ts` and `interaction-outbox.test.ts`.

## Usage read model

`usageRuntime` shares one aggregation service and source tracker per App scope between History, persisted agent-panel metrics, session accounting and export. Core `IUsageFactStore` maintains the journals at `cache/usage-facts-v1`; `IUsageReadModel` owns the independent typed database at `cache/usage-read-model-v2/index.sqlite`. History filters, prices, groups, counts exact turns and pages sessions in SQL without generic query-store folds. Ordinary session GET reads only published accounting or its metadata fallback, with `freshness` independent of `complete`; it never enumerates agents. `GET /api/usage/sessions/:sessionId/accounting` locates the session by index point read and advances one shared session flight within ten seconds, 100,000 wire records and 128 MiB. Repeating it continues committed progress; disconnecting a waiter does not stop publication. Targeted panel reads synchronize only requested agents and consume source/model/token-support-mask totals; settle reads retain their five-second, 100,000-record, 128 MiB limits and survive client disconnect. Prices are applied on explicit usage reads without rereading wire; a missing price on one record preserves other fully priced subtotals.

History verifies the full agent inventory and source generation, size, mtime and committed offset before treating the database as current. Its inventory cursor resumes across requests under the ordinary 500-session, 2048-source and ten-second limits, without relisting or reproving a completed prefix. A ready tracker permits ten-minute reuse; session-key changes synchronize only the dirty session, while a directory change or the fixed ten-minute repair requests a full inventory. Hot queries do not extend that deadline. Without a working tracker, History repeats full verification after each completed inventory. Published session accounting also expires after ten minutes and becomes stale on observed source or inventory changes. An external rewrite preserving size and mtime without an observed event remains undetected until another fingerprint changes. Bounded queries can exclude sources whose epoch mtime predates the range; an expanded range verifies them. Only unmatched sources enter journal import or canonical recovery, sharing the ordinary 200,000-fact allowance, including unknown/invalid facts; indexed SQL reads are not capped to that many occurrences. Explicit `wireRecordBudget` and panel `maxRecords` retain raw-record units. Committed source prefixes survive deadlines or cancellation and resume at their saved canonical offset.

Each SQL response uses one committed data revision and a current pricing snapshot. Page tokens bind normalized filters, data revision, price revision and the cost/session-id keyset; changes reject the token with `40922`, and clients restart from the first page. Equal fact values retain separate ordinals, while bucket turns deduplicate by session, effective agent and turn; session drilldown turns deduplicate by session and turn. Known zero, legacy zero, explicit unknown and rejected records retain distinct accounting states. `usageComplete` reports source coverage independently of `usagePartial` and `costPartial`; complete-but-unknown rows must not trigger repeated full settling. Identical History queries share a cancellable flight: one cancelled waiter leaves the others active, and the last waiter aborts unfinished preparation.

Canonical recovery retains the bounded framing/parser-worker lane in `usageRecovery`; storage reads and durable source publication remain host-owned. The npm bundle emits `usage-parser-worker.mjs`, and SEA supplies `kap-usage-parser-worker`. The separate typed SQLite worker is supplied by core. An explicit full rescan bypasses ordinary scan budgets, verifies every source and reports progress. Export reads the same source facts but retains its own content-free bucketing, anonymization and per-record quality rules. `readLegacyProjection()` and its parser are the explicit read-only legacy seam; old generic Usage collections and projection files remain untouched for rollback. Do not remove the shared query database or canonical journals when resetting Usage. Cache recovery instructions live in [data locations](../../docs/en/configuration/data-locations.md#session-and-usage-query-cache).

## Advanced session and MCP surfaces

`GET /api/sessions/query` (`src/routes/v2/sessions.ts`, registered by the unified route entry) provides the advanced session query. It shares the flat session routes' wire conventions: every response is wrapped in the `{ code, msg, data, request_id }` envelope with the business outcome in `code` (`40001` invalid query params with `details`, `40922` page_token mismatch), and the HTTP status only reports server-/transport-level outcomes (401 from the global auth hook, `50001` via the catch-all error hook). Pagination is an opaque `page_token` (base64url JSON: version + sha256 query-condition fingerprint + keyset position) — any condition flip mid-pagination fails 40922. Response domains are grouped (`workspace` / `meta` / `activity` always; `git` opt-in via `include=git`, deduped per unique cwd with a 60s TTL cache over `IGitService`, all git/gh failures degrading to cached null fields). Sorts/filters are applied at the edge over the index's canonical `updatedAt desc, id desc` drain, so all three sort orders share one comparator + cursor encoding; `activity.status` maps the core `ISessionActivityView` facts (pending interaction > active turn > failed last turn > idle; cold sessions are always `idle`).

`/api/mcp/*` (`src/routes/v2/mcp.ts`) exposes the agent-core-v2 `mcpManagement` plane: CRUD on the user-level `mcp.json` (`GET/POST/PUT/DELETE /mcp/servers[/{name}]`; `PUT` takes a name-less config body, the path owns the identity), a connection-test probe and the locator-addressed inspection catalog (`POST /mcp/servers:test` / `:inspect`, declared with the doubled-colon static-segment convention), the auth-status surface (`GET /mcp/auth-statuses?verify=`), and the locator-addressed OAuth flow operations (`POST /mcp/auth:begin|complete|cancel|reset`). Engine `Error2`s map `mcp.server_not_found` → `40408`, `request.invalid` / `config.invalid` → `40001`, and `mcp.oauth_failed` → `40929`. `auth:complete` is a long poll (up to the flow's `timeoutMs`): the server disables Node's default `requestTimeout` (`start.ts`), and the handler aborts the engine wait when the client connection closes early. The klient facade mirrors the same surface as `global.mcp.*` with identical wire codes, plus the name-only `global.mcp.resolveByName` helper (REST clients compose locators from the `GET /mcp/servers` catalog).

## Transcript surface

`TranscriptService` owns the derived projection checkpoint format. Bump it when replay semantics change: an accepted checkpoint seeds the snapshot, adapter and reducer, then resumes from its saved byte offset, so an EOF checkpoint cannot recover newly projected facts without invalidation. Format 13 rebuilds older checkpoints from unchanged canonical wire so an unanchored boundary injection lands on the running step already opened by anchored user frames while the step cursor still points at the previous step. It retains format 12's association of managed prompts and edited replacements with their logical `userMessageId`, and a replacement still starts in its own turn rather than as an appended delivery. It retains format 11's reported executor context usage and subagent task model, effort provenance, and executor identity. It retains format 10's semantic goal changes and full budget state without goal accounting notices. Format 9 repaired provider URL media references previously projected as session file IDs; format 8 introduced restored question request time. Replay prefers payload `createdAt`, then `created_at`, then the durable `interaction.request` record's `time`; absent all three, it leaves request time unset. Never rewrite wire or infer request time from the answer. A rebuilt current-format checkpoint remains reusable for unchanged wire and appended tails.

Transcript retention budgets apply across sessions and agents, not only to each wire: verified completed history shares a 64 MiB estimated resident allowance; each cold parsed window targets 8 MiB and all cold windows share 32 MiB; cold snapshots share 4 MiB; anchor windows retain at most four 8 MiB entries. Cold session snapshots keep a separate main-wire projection cache in `readColdMainWireProjection`. That cache is not part of the 4 MiB cold-snapshot allowance: it has its own 4 MiB total, a projection larger than 4 MiB is not retained, and the next unchanged read of that history reads the file again. Cancellation is checked after the file stat and before a retained projection is returned. A missing file is not cached; any other stat failure rejects. A cold window that exceeds the total allowance keeps only its fingerprint and byte boundary for older-page continuation, never its records, snapshot or headers. A fresh read reconstructs the original body on demand. Canonical detail keeps its own bounded cache and one bounded oversized entry. The shared history-read lane allows two active reads and eight waiters; excess requests receive `SESSION_BUSY`, and disconnect or disposal releases waiting work. Evicted op-journal slots clear their payload references immediately, not merely advance the logical head.

Completed live turns outside the cold tail window can be released independently of the whole-wire live epoch. After flush, residency maintenance prepares navigation once, pins its source generation and watermark, and replays each candidate's canonical spans under their exact digests. Replay advances in pages of at most 128 spans, 8 MiB and 50,000 records, closing read handles and yielding between pages. Equal resident strings are reused only after comparing canonical values; draft, adapter, durable-fact deduplication and string-index metadata count toward an 8 MiB estimated additional-retained-state threshold. Each record is admitted against an incremental upper estimate; a possible crossing reconciles the current graph, refunding replaced and temporary objects. A confirmed crossing rejects that proof before reading another record. The indivisible record Buffer (at most 8 MiB), UTF-8 decoding, JSON parsing and local traversal workspace are separate temporary allocations; the threshold is not a V8 heap-peak cap. Traversal uses depth-bounded iterators with cancellation and yields, never a whole-array entries copy. Only a complete proof of the unchanged resident entity releases store and binding payloads. Object key order and absent optional fields do not change persisted content; array order and actual values remain significant. Failed proofs are cached by resident identity and canonical turn revision, so unrelated appends do not replay them; source repair or entity changes permit retry. A record or additional proof state exceeding the allowance remains resident, as do missing, mismatched, unflushed and running facts. Canonical detail still rereads the full historical body on demand. Session or agent close aborts maintenance, including a pending flush wait. `test/services/transcript.test.ts` covers 220 agents across two sessions, a 34 MiB sole cold record, 288-frame proofs spanning multiple pages, durable deduplication across pages, missing and mismatched facts, source changes, cancellation and old-body rereads. With `--expose-gc`, the focused cases verify WeakRef collection and record heap usage after release and close.

Implements the op-batch sequencing contract:

- `TranscriptService.dispatchOps` assigns every dispatched batch a per-agent consecutive `seq` and retains it in a bounded in-memory journal (`TRANSCRIPT_OPS_JOURNAL_CAPACITY`, dies with the live store). WS `transcript.ops`/`transcript.reset` payloads carry the seq/watermark.
- A numeric `transcript_since` subscription cursor (carried, with the per-agent grades, by the `subscribe_v2` control frame — the only transcript subscription channel; its agent-grained counterpart `unsubscribe_v2` detaches listed agents' streams, or the whole session's when `agent_ids` is absent, letting the detached agents' legacy events flow again) replays journaled batches instead of a baseline reset when the journal covers it, and `GET /sessions/{id}/transcript/ops?since_seq=` serves point-to-point catch-up (`complete: false` = journal can't cover or session cold → caller falls back to a full refresh).
- Beside the paged route, `GET /sessions/{id}/transcript/plan?agent_id=[&tool_call_id=]` projects an agent's ExitPlanMode plan info (content / path / options / review outcome; `tool_call_id` narrows to one call, omitted lists every recoverable plan) from the first available fact — the linked approval interaction's persisted request display, the live tool frame's display, or the tool result output text.
- The baseline `transcript.reset` is a bounded snapshot (`TRANSCRIPT_RESET_TAIL_TURNS = 20`): the newest 20 turns plus global tasks/interactions/prompts/meta and `has_more_older`. `turn` grade redacts step/frame detail (roster/task/meta only); `delta` grade carries the visible timeline. GUI first-screen reads establish a bounded wire tail without waiting for whole-wire verification or navigation preparation. Initial live replay finishes from that tail before buffered live events drain; reset snapshots and their per-agent cursors share the resulting watermark. Counts and coverage remain unknown until their source is verified. Older pages and canonical detail retain their explicit recovery paths; an orphan turn's reset cursor requests its missing header before moving past it. `ensureAgentHistory` keeps its default behavior and `fullHistory` contract; only `tailFirst` callers use the first-screen path.
- Older-page HTTP reads enforce a five-second cancellable deadline. Wires up to the 1 MiB first-screen allowance retain the verified cold replay path; larger wires use bounded cold windows rather than replaying the whole file. Live pages check an existing epoch proof synchronously and start missing proof in the background; unverified reads keep coverage and counts unknown. The client's complete older-page demand has a ten-second deadline and stops after sixteen empty preparing batches. Failures preserve the current continuation, and late results cannot replace a successful retry.
- Initial `view.bootstrap` registers its target before reading the bounded transcript tail and snapshot shell in parallel. Transcript signals may arrive before the `snapshot` signal; durable session hints wait for the shell and reconcile its epoch/watermark. Reconnects use the normal checkpoint path. Existing `subscribe` and `ready` contracts remain unchanged.
- When a WS connection subscribes to the transcript protocol (grade ≠ `off` for an agent), the broadcaster suppresses the transcript-projected `session_event` types for that connection × agent (`TRANSCRIPT_PROJECTED_EVENT_TYPES` + `suppressedByTranscript` in `sessionEventBroadcaster.ts`; cursor replay via `getBufferedSince` applies the same filter). The set includes the prompt queue variants already projected as `prompt.upsert` (`prompt.queued`, `prompt.replaced`, plus submitted/completed/aborted/steered). Suppression is only a per-connection send view — the journal still records everything, and connections without transcript grades are unaffected.

## History navigation search

HistorySearch defaults to user/assistant text. `include_tool_output: true` or an explicit `role: 'tool'` adds tool-result output; thinking, tool names and call arguments are not searchable. Scope is bound into continuation cursors. Apply this filter when querying visible spans, not when projecting navigation: HistoryList and HistoryRead retain their full source view.

`services/history/historySortedSearch.ts` prepares the shared SQLite navigation projection through a fixed wire watermark before querying visible text spans. Preparation and text reads share an 8 MiB / 50,000-record per-call scan budget; bounded head/tail source-proof reads are separate validation IO. Projection slices capture their end offset before reading, including normal non-search preparation. Proof IO permits same-identity growth, rechecks the captured head/tail samples once, and retains the original stat revision; it rejects replacement, shrinkage and unchanged-size metadata changes. Canonical detail replay verifies exact span digests and serves the accepted manifest range even if later records append; a subsequent read advances navigation rather than treating that prefix as latest. `newest`/`oldest` use `(coalesce(time,0), key)` keysets across pages. `relevance` scores only the current newest-first scan page with the shared lexical matcher and reports `page_local_relevance` while unscanned candidates remain. New V2 cursors bind request, incarnation, projection generation and a bounded proof of their fixed source watermark; normal source appends do not invalidate them, but a changed prefix or a shared projection advanced beyond that watermark does. Older V2 cursors without a proof retain strict stat-fingerprint validation. V1 scan cursors retain source-order continuation with an explicit warning. Numeric HistoryRead and older HistoryList pages retain explicit preparation cursors; an empty preparation page is not a no-match result. A cold newest-first HistoryList without filters can expose explicitly numbered recent turns from a bounded tail before the shared projection is ready. `historyDirectoryWindow.ts` discovers at most 4 MiB and replays at most 4 MiB into an isolated, body-free metadata window, retaining at most two 4096-row windows. Implicit turns, visibility resets and unresolved cross-window identities use the original forward recovery path. Window refs bind byte boundaries and source proof and reconstruct the same turn blocks after restart; continuation fixes that watermark and preserves the last returned turn through preparation. Forward recovery uses an isolated namespace in the same navigation SQLite database, keyed by source proof and watermark, without rewinding the shared manifest. At most two fixed-prefix views are retained. Evicted fixed-prefix refs rebuild in 8 MiB / 50,000-record slices; HistoryRead v5 preparation cursors preserve the original ref, source watermark and directory or text-block read position across restart. Appends do not extend those blocks; source replacement and appended undo/clear invalidate the refs. Absolute source watermarks use `streamWireRecords*`'s `endByteOffset`, never the IO budget `maxBytes`. Search-order indexes are additive and removable; SQLite table schema stays at version 2, and all navigation rows remain rebuildable from canonical wire files.

## Session events

- The session's work aggregate behind `event.session.work_changed` (`busy` / `executing` / `main_turn_active` / `pending_interaction` / `last_turn_reason`) is owned by the core's `ISessionActivityView` (`sessionActivity` domain, Session scope). `busy` retains unfinished work through terminal-result delivery; `executing` reports live execution and finite process/media work, not queued work, resident services or stale agent task rows. Older hosts omit `executing`, meaning unknown. The broadcaster only schedules the wire emission around turn frames (`busy:false` lands after `turn.ended`), and `resolveSessionFacts` (`src/routes/sessions.ts`) reads the same view — never fold per-agent activity at the edge.
- Delivery split on `/api/ws`: global events (`session.meta.updated` and the `event.session.*` / `event.workspace.*` / `event.config.*` families, including every activated session's `event.session.work_changed`) fan out to EVERY established connection — `WsConnectionV1` registers itself via `broadcaster.addGlobalTarget` on construction and unregisters on close — while session/agent-grained events only reach connections subscribed to that session (subject to `agent_filter` and the transcript suppression above); transcript frames are a separate channel governed by the per-agent grades alone and bypass `agent_filter` entirely.

## Completion notifications

`NotificationService` owns stable work episodes and consumes `ISessionActivityView`; neither reconciliation nor completion GET enumerates agents. Core retains `busy` through finite task result delivery, running/finalizing/pending loops, active/queued/launching prompts, active Goals and starting/running/cancelling executions. Core caches per-agent work facts, updates counters only for dirty agents and coalesces background invalidations per session; task delivery and loop admission publish service-local `onDidChangeWork` signals after their state changes. `state()` flushes already-dirty facts before returning. Resident service tasks and future cron entries do not block completion. `GET /api/notifications/completions` exposes only ten-minute in-memory stable episode receipts (`session_id`, `episode_id`, `completed_at`) for the existing GUI notifier; no history replay or cold-session materialization. First observation without a saved cursor baselines the projection; reconnect and app reopen resume the home/connection/server-home-owned episode cursor instead of dropping newly completed episodes. Completed episodes deduplicate by episode id, not the attention cooldown. Neither transcript turn completion nor list `busy:false` can substitute for a receipt. GUI completion delivery is suppressed only while the same conversation is visible and focused, and seen marks advance only in that state. Notification clicks carry both home and connection scope. Native unread counts retain each scope independently and union known local sessions with background pending-input attention. IM delivery keeps its existing master, per-channel scene, viewing, quiet-hours and duration gates.

## Global search

`POST /api/search` (`src/search/` and `src/routes/search.ts`) uses only SQLite at `<home>/search-index-v2/index.sqlite`. During the 0.5 migration series, explicit `search_backend = 'minidb'` and `KIKI_SEARCH_BACKEND=minidb` are deprecated SQLite aliases with a migration warning; remove them or set `sqlite` before 0.6. The old `<home>/search-index` is preserved and never imported or used as fallback. `[search] enabled=false`, `KIKI_SEARCH_DISABLED=1`, and desktop `desktop_search=false` keep search off, including retry/reindex and background startup. The retired `search_worker` switch has no execution branch.

- `SqliteSearchHost` owns one 256 MiB query worker (16 MiB SQLite page cache, eight active slots, 32 waiters) and a writer child requesting 256 MiB in development or 384 MiB in SEA. Writer election uses an adjacent SQLite lease database and `BEGIN IMMEDIATE`; other hosts read only and retry election at 2s, 4s, 8s, 16s, then 30s. Query watchdog, shutdown drain, writer memory budgets and bounded restart ladders remain in `src/search/sqlite/host.ts`. Ordinary restart backoff is 1s, 10s, 60s, then 10 minutes. Memory-specific backoff begins at the third consecutive budget exit; the sixth stops until `POST /api/search/retry`.
- Both index and live routes default to user/assistant body text and titles. `include_tool_output: true` or role `tool` adds tool results; thinking, tool names and arguments stay excluded. `[search] index_subagents=true` enables truncated subagent indexing; by default only main-session content and titles are indexed. Role/workspace/container/time filters apply before candidate caps.
- `@kiki/lexical` owns the unchanged ASCII-word/CJK uni-bigram tokenizer and NFKC/lowercase literal normalization shared by Memory, history and search. Schema 2 stores each terms token as a boundary-delimited phrase of short UTF-8 hex chunks, preserving token equality, fullwidth punctuation and the 65535-character term limit through FTS5. Older recognized derived schemas are rebuilt from canonical sources. Literal queries use normalized trigram candidates, two-character CJK terms or bounded short-literal scans; final `includes` confirmation preserves exact substring semantics.
- The default terms/score route uses FTS5 rank with a 64-document cap and reports `candidate_cap` on overflow. Other paths retain their candidate/text/deadline budgets. Identical queries coalesce for at most 500 ms and invalidate on SQLite `data_version`. Cache source-identity verification and at most one requery share the request's absolute deadline and remaining candidate/text allowances; expired verification returns `incomplete='deadline'`, without waiting for the worker watchdog. Session deletion/replacement cannot be hidden by that cache.
- Sync runs in the child, publishes committed progress and serves partial building pages. The service keeps a warm summary/mtime inventory with targeted source watching, a ten-minute stat repair and a thirty-minute inventory refresh. Revision-tagged full inventories arrive in 1000-session pages; the indexer retires missing sessions and their FTS/file rows in bounded batches before acknowledging the inventory. Per-file append watermarks remain incremental; same-length rewrites with changed mtime replace the file's derived rows even when its tail is unchanged. `reindex()` supports cold startup, clears owned derived rows and resyncs canonical sources; a read-only host rejects it. `status().indexer` exposes RSS/WAL/progress; `lifecycleReport()` is local and never starts workers.
- Indexed keyset cursors bind query/scope, source route and SQLite generation. Live searches use a 60-second, eight-entry continuation cache for bounded resident extraction and the shared history-navigation SQLite cursor for missing history; neither route requests `fullHistory`. The live request's absolute deadline and disconnect signal cover readiness, extraction, tokenization and navigation. Resident calls visit at most 4096 nodes and retain at most 4096 matches; navigation prepares and reads at most 128 KiB / 512 records per call, with oversized-record fallback disabled. `coverage` reports pending scans, skipped history and page-local ordering; `incomplete='scan_budget'` is never a complete no-match result. Continuations reuse completed preparation, and changed resident state, an expired live cursor, source replacement or a live/index route flip rejects the token as `invalid_page_token`. Internal injections stay excluded and live errors never fall back. Scores are comparable only within a route.
- npm emits `sqlite-indexer.mjs` and `sqlite-query-worker.mjs` through `apps/kimi-code/tsdown.dist-sqlite.config.ts`. SEA dispatches `__search-indexer` before normal bootstrap and embeds the SQLite query worker. Tests clear inherited worker-path overrides so source checks cannot accidentally execute an installed runtime asset.
